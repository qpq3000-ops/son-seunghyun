## 1. API 계약 (패키지 간 유일 접점)

### 1.1 신규 — `GET /api/gl-vouchers` (E 전표조회, 서버 패키지)

`server/accounting.mjs`에 `/journal`(235행) 바로 뒤에 추가. **읽기 전용**, 기존 `journal`/`journal_line`/`partner` 조인, 전표(journal) 단위 1행. 신규 테이블 없음.

파라미터: `from`(YYYY-MM-DD, 기본 이달1일), `to`(기본 오늘). 응답:

```jsonc
[
  { "journal_id": 12, "io_date": "2026-07-06", "doc_no": "20260706-2",
    "entry_type": "매출",            // journal.entry_type (매출/매입/수금/지불/일반)
    "source_menu": "매출전표Ⅰ",       // entry_type→입력메뉴 매핑(서버계산, 아래 표)
    "amount": 3553000,              // Σ(journal_line.dr) per journal
    "partner_name": "○○카페",       // partner.name 또는 null
    "summary": "bco 블랜딩 외 3건" } // journal.summary
]
```

- **입력메뉴 매핑**(`source_menu`): `매출`→`매출전표Ⅰ`, `매입`→`매입전표`, `수금`→`입금보고서`, `지불`→`지출결의서`, `일반`→`지출결의서`. (실물 예: 매출전표Ⅰ·지출결의서·매출처로부터·입금보고서 — 근사 매핑, 주석으로 명시)
- SQL:
  ```sql
  SELECT j.id AS journal_id, j.io_date, j.doc_no, j.entry_type, j.summary,
         p.name AS partner_name,
         (SELECT COALESCE(SUM(jl.dr),0) FROM journal_line jl WHERE jl.journal_id=j.id) AS amount
  FROM journal j
  LEFT JOIN partner p ON p.id=j.partner_id
  WHERE j.io_date>=? AND j.io_date<=?
  ORDER BY j.io_date DESC, j.id DESC
  ```
  `from/to`는 `isValidDate`로 검증 후 `monthStartISO()/todayISO()` 폴백(같은 파일 관례). `source_menu`는 JS map으로 부여. 결과 없으면 `[]`.

### 2.2 [생산]/[소모] pill 토글
- `산출 원두`/`투입 생두` 두 섹션 위에 `▶ 생산품목` 헤더 + `.r8-pills`: `[생산]`(on 기본)/`[소모]`. 로컬 state `mode:'생산'|'소모'`.
- `mode==='생산'` → 산출 원두 섹션(+ 산출 그리드) 표시, `mode==='소모'` → 투입 생두 테이블 표시. **감춰진 섹션의 state는 보존**(조건부 렌더만, unmount 시에도 상태 유지되도록 `display:none` 토글 권장 — React state는 상위 컴포넌트에 있으니 조건부 JSX여도 state는 유지됨). save는 두 state 모두 사용하므로 무영향.
- 두 섹션을 동시 노출하던 기존 레이아웃 → 토글 전환. 기본 `생산`.
