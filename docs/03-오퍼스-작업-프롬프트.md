# 03. 오퍼스 4.8 작업 시작 프롬프트

> 사용법: Claude Code에서 모델을 **Opus 4.8**로 설정하고, 이 저장소를 연 상태에서 아래 프롬프트를 순서대로 붙여넣는다.
> 한 세션 = 한 Phase 를 권장 (컨텍스트가 길어지면 품질이 떨어지므로 Phase가 끝나면 커밋하고 새 세션 시작).
> 각 Phase가 끝나면 반드시 `npm start`로 직접 실행해보고, 이상한 점을 다음 프롬프트에 적어서 시작한다.

---

## ① 마스터 프롬프트 (Phase 0 — 최초 1회, 이것부터)

```
너는 지금부터 "로스팅 ERP" 프로젝트의 단독 개발자다. 나는 커피 로스팅 사업자이고,
이카운트(ECOUNT) ERP의 기능·업무흐름·화면 패턴을 카피 수준으로 재현한 개인용 ERP를
이 저장소에 만든다. 배포는 하지 않고 내 PC에서 나 혼자 로컬로 쓴다.

## 먼저 읽어라 (순서대로, 반드시 전부)
1. docs/00-현재-업무-분석.md — 내 실제 업무와 기존 앱(index.html)의 기능. 이 강점들은 반드시 보존된다.
2. docs/01-프로젝트-기획서.md — 범위(In/Out), 기술 스택, 데이터 모델 규칙, 메뉴맵, Phase 로드맵. 이 문서가 최상위 스펙이다.
3. docs/02-이카운트-기능-분석.md — 이카운트 140개 메뉴의 상세 스펙(필드/기능/보고서). 각 화면을 만들 때 해당 메뉴 섹션을 다시 찾아 읽고 그대로 재현하라. (확인필요) 표시는 합리적으로 구현하고 목록으로 보고하라.

## 고정 사항 (변경 금지, 대안 제시 불필요)
- 스택: Vite + React + TypeScript(SPA) / Tabulator(MIT) 그리드 / Hono + better-sqlite3 / 단일 DB 파일 data/erp.sqlite / 인쇄는 @media print CSS
- 금액은 원 단위 정수(INTEGER), 부가세 = 공급가액×10% 원미만 절사(환경설정으로 반올림 선택 가능하게)
- 수량은 kg 소수 1자리(0.1 단위 스텝)
- 재고는 append-only 수불원장(stock_ledger)으로만 움직인다. 재고현황/수불부는 전부 이 원장의 집계다. 전표 수정·삭제 시 관련 원장 행을 재작성한다.
- 전표는 공통 구조(doc 헤더 + doc_line 라인 + doc_type 구분)를 공유한다. 견적/주문/판매/발주/구매를 별도 테이블로 만들지 마라.
- 회계 분개는 journal/journal_line, 저장 시 차변합계=대변합계를 서버에서 강제.
- Firebase 등 외부 서비스 의존 금지. 완전 오프라인 동작. 한국어 UI.
- 이카운트의 코드/이미지/문구를 그대로 복사하지 말 것. 기능과 화면 개념만 재현한다.

## 이번 세션의 작업: Phase 0 (뼈대)
docs/01 문서의 "Phase 0" 범위를 구현하라:
1. 프로젝트 셋업 — 루트에 client/(Vite React TS) + server/(Hono + better-sqlite3) + 루트 package.json에서
   npm start 한 번으로 서버 기동 + 브라우저 자동 오픈까지. Windows용 시작.bat 포함.
2. DB 마이그레이션 시스템(버전 관리되는 SQL 파일) + 마스터 테이블: item, partner, warehouse, price_special, project, settings
3. 공통 UI 컴포넌트 (이후 모든 메뉴가 재사용):
   - AppShell: 상단 대메뉴 바(대시보드/영업/구매/생산/재고/회계/일정/기초등록/설정) + 멀티 탭(MDI, 여러 화면 동시 오픈) + 즐겨찾기(☆)
   - SearchPanel: 기간/거래처/품목/창고 검색조건 패널
   - DataGrid: Tabulator 래퍼 (인라인 편집, 정렬, 하단 합계행, 엑셀 다운로드)
   - CodeHelp: 거래처/품목 검색 선택 팝업 (입력칸에서 키보드로 열고 선택)
   - VoucherForm: 전표 공통 폼(상단 헤더 + 하단 품목 라인 그리드, 수량×단가→공급가액→부가세 자동계산, 저장 후 연속입력)
   - Toast, ConfirmDialog, 원화/수량 포맷 유틸
4. 기초등록 4종 화면: 품목등록(품목구분: 원재료/부자재/제품/상품, 단위, 입출고단가, 안전재고), 거래처등록(입금주기: 당일/월별, 연락처, 메모), 창고등록(창고/공장 구분), 단가관리(거래처×품목 특별단가)
   — 각 화면을 만들기 전에 docs/02의 해당 메뉴 섹션(품목등록/창고등록/단가관리)을 다시 읽고 필드를 맞춰라.

## 작업 방식
- 시작 전에 구현 계획(파일 구조, 스키마 DDL)을 먼저 보여주고 진행하라.
- 완료 기준: npm start 한 번에 실행되고, 품목·거래처를 등록/수정/삭제할 수 있고, 특별단가가 저장되고, 탭 여러 개를 열고 닫을 수 있다.
- 끝나면 직접 서버를 실행해 API를 검증하고, 남은 이슈/(확인필요) 목록과 함께 커밋하라.
```

## ② Phase 1 프롬프트 (영업·구매·재고 코어)

```
docs/00, 01, 02를 다시 읽어라. Phase 0(뼈대, 기초등록)은 완료된 상태다.
이번 세션은 docs/01의 "Phase 1: 영업·구매·재고" 전부를 구현한다.

1. 전표 엔진: doc(전표번호 자동채번, 일자, doc_type, 거래처, 창고, 상태, source_doc_id) + doc_line.
   저장 트랜잭션 안에서 stock_ledger 기록까지 원자적으로 처리. 수정/삭제 시 원장 재작성.
2. 영업: 주문서입력/조회 → 판매입력/조회(끌어오기: 주문서 선택→판매 전환, 원본 진행상태 갱신)
   → 수금입력 → 미수금현황(거래처별 채권 잔액, 입금주기 표시, 월별 거래처 일괄수금 버튼).
   주문서입력 화면에는 기존 앱의 "거래처 주문 누락 체크"(주문 없는 거래처 빨간 표시)를 포함하라. 견적서는 주문서와 같은 엔진이므로 함께.
3. 구매: 발주서입력/조회 → 구매입력/조회(끌어오기) → 지불입력 → 미지급금현황.
4. 기타이동: 창고이동, 자가사용, 불량처리(폐기/정상사용/품목대체), 재고조정(재고불러오기→실사수량 입력→조정 반영).
5. 출력물: 재고현황(기준일자), 창고별재고현황, 재고수불부(이월/입고/출고/현재고, 입출고 유형별 세분), 판매현황/구매현황(기간/거래처/품목별 집계, 합계행).
6. 거래명세서 인쇄: 판매 전표에서 A4 @media print 양식(공급자 정보는 settings에서). 견적서 양식도.
7. 기존 데이터 이관: index.html 앱의 JSON 백업 구조(00 문서 참고)를 읽어 거래처/품목/주문/미수금/생두구매를 DB로 가져오는 이관 화면(설정 > 데이터 이관).
각 화면 착수 전 docs/02의 해당 섹션을 읽고 필드·기능·보고서를 맞춰라.
완료 기준(직접 검증하라): 주문→판매→수금 한 사이클 후 재고현황·미수금·수불부 숫자가 수기 계산과 일치. 발주→구매→지불도 동일. 거래명세서가 인쇄 미리보기로 정상 출력.
```

## ③ Phase 2 프롬프트 (생산 = 로스팅)

```
docs/00, 01, 02의 생산관리 부분을 다시 읽어라. 이번 세션은 Phase 2: 생산(로스팅)이다.

1. BOM등록: 제품(원두) → 원재료(생두) 소요량 + 수율%(로스팅 중량 손실 반영, 예: 수율 85% = 완제품 1kg에 생두 1.176kg).
   부자재(포장봉투 등)도 라인으로 추가 가능.
2. 로스팅시트(작업지시서): 날짜 선택 → 해당일 주문서의 품목별 합산 → 배치 수 자동계산(환경설정의 배치 용량, 기본 5kg, 올림)
   → 배치 로스팅 순서 조정(위/아래 이동) → 인쇄용 시트 출력. 기존 앱의 로스팅시트 UX(00 문서)를 그대로 승격하라.
3. 생산입고: 로스팅시트에서 끌어오기 → 저장 시 생산전표생성(BOM 기준 생두/부자재 차감 + 제품 입고를 한 전표로) + 배치 로트번호 자동 생성(예: R20260710-1).
   실제 투입량/산출량을 수정 입력할 수 있어 실측 수율이 기록된다.
4. 생산현황/수율분석: 기간별 생산 내역, 품목별 계획 대비 실적, 배치별 실측 수율 추이.
5. 소요량계산(간이 MRP): 미출고 주문 기준 필요 생두량 vs 현재고 → 부족분 표시(발주 참고용).
6. 달력 통합: 월 달력에 로스팅일(완료/예정 색 구분)·일별 kg 합계 표시, 날짜 클릭 시 해당일 주문/생산으로 이동. 기존 앱 달력 UX 유지.
완료 기준: 주문입력→로스팅시트→생산입고→판매전환→거래명세서까지 한 회차가 ERP만으로 끝나고, 생두 재고가 수율 반영되어 정확히 차감된다.
```

## ④ Phase 3 프롬프트 (회계)

```
docs/01, 02의 회계관리 부분을 다시 읽어라. 이번 세션은 Phase 3: 회계다.

1. 계정과목 마스터(기본 세트 시딩: 현금, 보통예금, 외상매출금, 외상매입금, 원재료, 제품, 매출, 매입, 부가세예수금, 부가세대급금, 주요 판관비 등) + 거래유형(과세/면세).
2. 자동분개 엔진: 판매/구매/수금/지불 전표 저장 시 분개 자동 생성.
   판매(과세): 차) 외상매출금 / 대) 매출, 부가세예수금. 구매: 차) 원재료·상품, 부가세대급금 / 대) 외상매입금. 수금: 차) 보통예금 / 대) 외상매출금. 지불은 반대.
   전표 수정·삭제 시 분개 재작성. 차대변 불일치는 서버에서 저장 거부.
3. 일반전표(경비 입력): 임차료/전기료/소모품 등 차대변 직접 입력(간단 UI, 자주 쓰는 패턴 즐겨찾기).
4. 장부: 분개장, 계정별원장, 거래처원장(채권/채무 상세), 현금출납장.
5. 매입매출장: 기간별 공급가액/부가세 집계(부가세 신고 참고자료, 과세/면세 구분).
6. 월별손익: 월 매출-매출원가-경비 = 이익 표. 12개월 가로 비교.
7. 자금현황: 계좌(통장/현금) 마스터 + 수금/지불/경비의 계좌 연결 → 계좌별 잔액과 일별 입출금.
완료 기준: 기존 전표들의 분개가 전부 생성되어 시산표가 차대변 일치하고, 월별손익 숫자가 판매현황/구매현황/경비 합계와 일치한다.
```

## ⑤ Phase 4 프롬프트 (마감 품질 — 기존 앱 은퇴)

```
docs/00, 01, 02를 다시 읽어라. 이번 세션은 Phase 4: 마감 품질이다. 목표는 index.html 없이 모든 업무가 가능해지는 것.

1. 메인 대시보드(포틀릿): 오늘/예정 로스팅, 주문 누락 거래처, 미수금 TOP(입금주기 지난 곳 강조), 안전재고 미달 품목, 이번달 매출/매입/이익 요약.
2. 거래처 메시지: 주문확인/택배안내 템플릿 + 해당일 주문 내역 자동 삽입 → 수정 → 클립보드 복사. 거래처별 수정본 저장(기존 앱 그대로).
3. 생두 단가비교: 생두별 최근 구매가/최저가(업체) 비교표, 월별 구매 합계(기존 앱 그대로).
4. 집계표(일별/월별/거래처별/품목별/담당자별)와 이익현황(판매가-원가 마진).
5. 엑셀 IO: 주요 마스터/전표/현황의 XLSX 다운로드, 마스터 엑셀 업로드(웹자료올리기 방식: 양식 다운로드→작성→업로드).
6. 자동백업: 서버 시작 시 + 전표 저장 50회마다 data/backup/에 타임스탬프 사본, 보관 개수 제한. 백업 목록/복원 화면.
7. 인쇄양식: 거래명세서/견적서/로스팅시트 양식 2종 이상(간단형/상세형) 선택 저장.
8. 안전재고 경고: 전표 저장 시 안전재고 미달 품목 경고 표시 + 재고현황에서 미달 품목 붉은 표시.
9. 환경설정 화면: 회사정보(인쇄용), 부가세 절사/반올림, 배치 용량(kg), 백업 주기.
완료 기준: 00 문서의 "반드시 보존해야 할 강점" 6개가 전부 ERP 안에 존재하고, 한 주간 업무 시나리오(01 문서 5장)를 처음부터 끝까지 ERP만으로 수행할 수 있다.
```

## ⑥ 화면 보정 프롬프트 (수시 사용 — "진짜 카피"를 위한 도구)

실제 이카운트 화면과 다르게 느껴지는 메뉴가 있으면, 마이크로소프트 엣지에서 이카운트의 해당 화면을 **스크린샷** 찍어 Claude Code에 첨부하고:

```
첨부한 스크린샷은 실제 이카운트 ERP의 [메뉴명] 화면이다.
내 ERP의 같은 화면([파일 경로 또는 메뉴명])을 이 스크린샷의 구성에 맞게 보정하라:
- 항목 배치, 컬럼 구성/순서, 버튼 위치와 명칭, 검색조건 항목을 스크린샷 기준으로.
- 다만 색상/아이콘/로고는 복사하지 말고 우리 테마를 유지한다.
- docs/02의 해당 섹션과 스크린샷이 다르면 스크린샷을 우선하고, 문서의 (확인필요) 항목을 확인 결과로 갱신하라.
```

> 이 방법이 "카피 수준" 완성도의 핵심이다. 02 문서는 공개 자료 기반이라 세부 배치에 오차가 있을 수 있는데, 실화면 스크린샷이 그 오차를 없애준다. 자주 쓰는 화면(판매입력, 재고현황 등)부터 보정하는 것을 추천.

## ⑦ 진행 팁

1. **Phase 순서를 지켜라** — 특히 Phase 0의 공통 컴포넌트와 Phase 1의 전표 엔진이 전체 품질을 결정한다. 서두르지 말 것.
2. **Phase 완료마다 커밋** — "Phase N: ..." 메시지로. 문제가 생기면 되돌릴 수 있다.
3. **숫자 검증을 직접** — 각 Phase 완료 기준에 있는 "수기 계산과 일치" 확인은 본인이 계산기로 해보는 것이 가장 확실하다.
4. **새 세션에서 시작할 때** — 항상 "docs/00, 01, 02를 읽어라"가 프롬프트에 들어 있는지 확인. 이 문서 3개가 프로젝트의 기억이다.
5. **불편은 즉시 프롬프트로** — 쓰다가 불편한 것은 "판매입력에서 저장 후 커서가 거래처로 안 돌아온다. 고쳐라"처럼 구체적인 현상으로 요청하면 된다.
