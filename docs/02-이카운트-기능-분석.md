# 02. 이카운트 ERP 기능 분석 (클론 스펙 카탈로그)

> **목적**: 이카운트(ECOUNT) ERP 5.0의 기능을 메뉴 단위로 전수 조사하여, "카피 수준" 클론을 만들기 위한 스펙 원본으로 사용한다.
>
> **조사 방법**: 이카운트 공식 기능소개 페이지, 공식 교육 교재(PDF), 사용법 블로그/컨설팅 자료 등 공개 자료를 병렬 리서치(7개 영역 × 전담 조사 + 그룹웨어/UI 보강 조사)로 교차 확인. 로그인 세션 화면은 외부에서 접근 불가하므로, 실제 화면과 다른 부분은 사용자가 이카운트 화면을 보며 보정한다.
>
> **표기 규칙**: `(확인필요)` = 공개 자료에서 완전히 검증하지 못한 항목. 구현 시 이카운트 실화면과 대조할 것.
>
> **저작권 방침**: 복제 대상은 **기능·업무 흐름·화면 구성 개념**이다. 이카운트의 코드, 이미지, 아이콘, 문구를 그대로 가져오지 않고 전부 자체 제작한다. 개인 사용 목적이며 배포하지 않는다.

## 0. 이카운트 ERP 전체 구조 (조사 종합)

이카운트는 상단 대메뉴 아래 기능이 묶이는 구조다. 조사로 확인된 대메뉴와 하위 영역:

```
재고Ⅰ ─ 기초등록(품목/창고/단가관리) · 구매관리(발주요청/발주계획/발주서/구매)
        · 영업관리(견적서/주문서/판매/수금/출하) · 생산/외주(BOM/작업지시서/생산불출/생산입고/소요량계산)
        · 기타이동(창고이동/자가사용/불량처리/재고조정) · 출력물(재고현황/수불부/집계표 등)
재고Ⅱ ─ 시리얼/로트No. · WMS · 바코드 · 이익관리(원가생성) · 계획관리(생산계획/매출계획)
회계Ⅰ ─ 기초등록(계정과목/거래처) · 매출매입거래(매출전표/매입전표) · FastEntry(일반전표/지출결의서/입금보고서 등)
        · 장부(분개장/총계정원장/계정별원장/현금출납장/매입매출장/거래처원장) · 결산재무제표(시산표/재무상태표/손익계산서/원가명세서)
        · 전자(세금)계산서 · 부가세신고 · 계좌/카드연동
회계Ⅱ ─ 자금관리(자금일보/일일자금/예적금) · 자금계획 · 예산 · 고정자산 · 비용관리 · 수입비용
관리   ─ 인사관리(인사카드/발령) · 급여관리(수당공제/급여계산/명세서/퇴직/연말정산) · 근태관리
세무   ─ 원천세 · 기타원천세
그룹웨어 ─ 전자결재 · 게시판 · 일정관리 · 쪽지/알림 · 업무관리(출퇴근기록/업무일지/ToDo) · CRM · 파일공유
Self-Customizing ─ 환경설정(기능설정) · 입력화면설정 · 인쇄 양식설정 · 사용자/권한 · MY메뉴/즐겨찾기
```

이하 각 모듈의 메뉴별 상세 스펙. **굵은 필드/기능 목록이 곧 구현 체크리스트다.**

## 재고관리 (재고Ⅰ/재고Ⅱ)

> **화면 특징**: 100% 웹기반(브라우저/모바일 앱 동일 기능). 전표 입력화면은 공통적으로 '상단 헤더(일자·거래처·창고·거래유형·프로젝트 등 건 단위 정보) + 하단 그리드(품목·수량·단가 복수 라인, 라인삽입 지원)' 2단 구조이며 공급가액/부가세는 자동계산(직접수정 불가). 모든 입력 메뉴 우측 상단에 [Option] 버튼이 있어 입력화면설정(항목 추가/삭제/이름변경/순서변경), 금액조정항목설정, 안전재고설정 등 셀프커스터마이징이 가능하고, 출력물은 [양식] 선택/양식설정으로 인쇄 레이아웃을 바꾼다. 기초등록 화면(품목등록·창고등록)은 좌측 리스트 그리드 + 하단 [신규] 버튼 + 상세 팝업(탭 구조: 품목정보/수량/단가/관리대상) 패턴. 출력물(현황/수불부)은 상단 검색패널(기간·창고·품목·기타옵션) + 결과 그리드 구조로 엑셀 업로드(웹자료올리기/엑셀자료올리기)와 다운로드를 지원. 안전재고 미만 품목은 현황 그리드에서 붉은색 표시. 전표 간에는 '전표불러오기'(발주→구매, 주문→판매)와 진행상태변경(완료 처리), 전표추적(시리얼/로트) 기능으로 연결된다. 메뉴 트리는 재고Ⅰ(기초등록/영업관리/구매관리/생산·외주/기타이동/출력물)과 재고Ⅱ(시리얼·로트No./WMS/바코드/이익관리)로 분리되어 있다.


### 재고Ⅰ > 기초등록 > 품목등록

재고관리의 기준이 되는 품목 마스터를 등록/수정하는 메뉴. 품목코드 단위로 모든 재고수불·원가·단가가 관리된다.

**주요 필드**: 품목코드 (필수, 고유키) · 품목명 · 규격 · 단위 (EA/BOX 등, 단위당 단가 기준) · 입고단가 (부가세 포함 여부 선택) · 출고단가 (부가세 포함 여부 선택) · 바코드 (번호 임의입력 또는 자동생성 설정) · 품목구분 (원재료/부재료/제품/반제품/상품 등 — 유통·도소매업은 주로 '상품'만 사용) · 세트여부 (묶음상품이면 '사용' 체크) · 안전재고수량 (수량 탭 또는 입력화면설정으로 기본 탭에 추가) · 당수량 (수량 탭, 1/1 설정 시 규격계산 기능 활성화) · 시리얼/로트 사용여부 (관리대상 탭)

**기능**:
- 탭 구조: 품목정보(기본) 탭 / 수량 탭 / 단가 탭 / 관리대상 탭 (시리얼/로트 설정)
- 관계설정: 대표품목(EA)과 연결품목(BOX)을 환산수량으로 연결 — 입고는 BOX, 출고(판매/자가사용/불량처리/생산소모)는 EA로 처리, 재고현황/수불부에서 대표품목 환산수량 또는 개별수량 표시 선택
- 안전재고 설정: 재고전표 입력 시 안전재고 이하로 떨어지면 체크(경고)해주는 기능 — 적용 메뉴: 주문서, 판매, 생산불출, 생산입고, 창고이동, 자가사용, 불량처리
- 창고별 안전재고수량 설정: 각 메뉴 우측상단 Option > 품목별/창고별 안전재고설정, 웹자료올리기/엑셀자료올리기로 일괄등록
- Option > 입력화면설정: 항목 추가(예: 안전재고수량을 기본 탭에 추가), 항목명 변경, 입력순서 지정
- 웹자료올리기/엑셀자료올리기로 품목 일괄등록, [품목등록자료 변경하기]로 기존 자료 일괄수정
- 바코드 항목에 번호 입력 시 시스템 내 해당 번호의 바코드 생성 (자동생성 방식 설정 가능)
- 세트품목: 세트여부 '사용' 후 재고Ⅰ > 생산/외주 > BOM(소요량)에서 구성품(부속품목) 소요량 등록, BOM(소요량)조회 > [세트]탭에서 구성품 확인
- 환경설정 > 기능설정 > 재고 탭에서 추가수량 관리 여부 설정
- 적정재고수량 항목 및 발주 자동계산 연계 — 현재고·안전재고·최소구매단위·미입고수량·미판매수량 기반 적정 발주수량 자동계산 (품목등록상 필드 구성은 확인필요)
- 검색항목/추가항목(사용자 정의 문자·숫자 항목) 설정 (확인필요)

**관련 보고서/출력물**: 품목별 재고현황, 재고수불부, BOM(소요량)조회


### 재고Ⅰ > 기초등록 > 창고등록

재고를 보관·관리하는 창고와 생산이 일어나는 공장을 등록하는 메뉴. 창고/공장 단위로 재고수량 파악과 수불관리가 이루어진다.

**주요 필드**: 창고코드 (임의 지정) · 창고명 (실제 창고 이름) · 구분: 창고 / 공장 / 공장(외주비관리) · 생산공정 (구분을 '공장' 또는 '외주공장' 선택 시 활성화)

**기능**:
- 하단 [신규] 버튼으로 등록
- 구분 '창고': 단순 입출고 관리용 저장공간 (유통/제조 공통)
- 구분 '공장': 입출고 관리 + 생산관리 (우리회사 공장, 생산공정 존재 시)
- 구분 '공장(외주비관리)': 입출고 관리 + 외주생산관리(외주비 포함, 거래처 공장)
- 창고별 재고관리 여부 설정 가능 (예: 100 본사창고-재고관리함 / 200 매장창고-재고관리안함)
- 담당자별 창고 사용권한 제한 (확인필요)

**관련 보고서/출력물**: 창고별재고현황, 재고수불부(창고별 조회)


### 재고Ⅰ > 기초등록 > 단가관리
*메뉴명: 단가관리 (특별단가등록/단가적용순서설정)*

품목별 기본단가 외에 거래처별·창고별·그룹별 단가표(특별단가)와 단가 적용 우선순위를 관리하는 메뉴.

**주요 필드**: 특별단가그룹명 · 거래처설정 (그룹에 연결할 거래처 추가) · 품목설정 (품목별 단가 등록) · 단가적용순서 (최종단가 사용 체크)

**기능**:
- 특별단가등록 > [특별단가그룹] 탭 > 하단 [신규] > 거래처설정 클릭 > 하단 [추가]로 거래처 연결 > 품목설정 클릭 > 하단 [신규]로 품목별 단가 설정
- 거래처별/창고별/그룹별 단가표를 만들어 판매·구매 입력 시 자동 적용
- 단가적용순서설정에서 '최종단가 사용' 체크 — 판매/구매단가 적용 우선순위 설정
- 품목등록의 기본 입고단가/출고단가와 특별단가 간 우선순위 적용
- 거래처를 그룹으로 분류하여 그룹 단위 단가 적용
- 판매단가 다중 등록(단가 레벨 A~J 등) (확인필요)
- 할인율 기반 단가 자동계산 (확인필요)

**관련 보고서/출력물**: 단가표 조회/출력 (확인필요)


### 재고Ⅰ > 구매관리 > 구매입력

구매(입고) 전표를 입력하는 메뉴. 저장 시 모든 재고장부의 수불내역에 입고수량이 자동 반영된다.

**주요 필드**: 일자 · 거래처 (구매처, 검색 선택) · 입고창고 · 거래유형 (부가세율적용/부가세율미적용 — 과세/면세 구분) · 프로젝트 · 품목 (하단 라인) · 수량 · 단가 · 공급가액 (자동계산, 직접변경 불가) · 부가세 (자동계산, 직접변경 불가)

**기능**:
- 상단(거래 건 기본정보) + 하단(품목별 복수 라인) 2단 구조
- 발주서 전표불러오기로 발주 내역을 구매입력으로 전환
- 하단 '발주서 진행상태변경' 체크 후 완료 선택하여 저장 — 발주 마감 처리
- 저장 시 재고수불부 입고수량 자동 반영
- 바코드 스캔으로 품목 라인 입력 가능
- 시리얼/로트 관리 품목은 입고 시 로트번호 입력([선택] 버튼)

**관련 보고서/출력물**: 구매현황 (기간설정 검색), 발주 대비 미입고현황, 재고수불부


### 재고Ⅰ > 구매관리 (발주요청/발주계획/발주서/구매)
*메뉴명: 구매관리(발주) 관련 메뉴*

발주요청 → 발주계획 → 발주서 → 구매(입고)로 이어지는 기본 구매 프로세스를 관리한다.

**주요 필드**: 발주일자 · 구매처 · 품목/수량/단가 · 입고예정일 (확인필요)

**기능**:
- 발주요청, 발주계획, 발주서, 구매 등으로 기본 구매현황 관리
- 적정 발주수량 자동계산: 현재고, 안전재고, 최소구매단위, 미입고수량, 미판매수량 기반
- 자재소요계획(MRP)과 연계하여 발주수량·입고시기 계산
- 발주 대비 미입고 수량 보고서로 구매 진행상황 파악

**관련 보고서/출력물**: 발주현황, 발주미입고현황, 구매현황


### 재고Ⅰ > 영업관리 > 판매 > 판매입력

판매(출고) 전표를 입력하는 메뉴. 저장 시 재고수불부 출고수량에 반영되어 재고가 감소하며 거래명세서를 즉시 출력할 수 있다.

**주요 필드**: 일자 (거래명세서/인수증 날짜) · 거래처 (판매처) · 출하창고 · 담당자 (확인필요) · 거래유형 (과세/면세) · 프로젝트 · 품목 (하단 라인) · 수량 · 단가 · 공급가액/부가세 (자동계산) · Title 항목 (건 제목, 시스템 업그레이드로 추가)

**기능**:
- 상단(기본정보) + 하단(품목 복수 라인) 구조, 라인 삽입 기능
- 저장(전표) 버튼 클릭 시 전표 저장과 동시에 거래명세서 출력
- 상단 [+]생산입고 버튼: 세트품목 우측 '생산전표생성' 체크 시 판매와 동시에 세트 생산입고(구성품 차감·세트품 입고) 자동 처리
- 기본입력화면설정으로 항목 추가/항목명 변경/입력순서 변경
- 주문서/견적서 전표불러오기로 판매 전환 (확인필요)
- 안전재고 이하 출고 시 경고 체크 기능
- 바코드 스캔 입력, 모바일 앱에서 카메라 스캔으로 판매전표 생성 후 ERP 전송
- 거래처별 특별단가/최종단가 자동 적용

**관련 보고서/출력물**: 판매현황 (재고Ⅰ > 영업관리 > 판매현황), 거래처출고현황, 재고수불부, 거래명세서 출력


### 재고Ⅰ > 영업관리 > 판매 > 판매입력Ⅱ

매장 POS 운영에 최적화된 판매입력 화면. 카드단말기/VAN 연동 및 할인 처리를 지원한다.

**주요 필드**: 일자 · 거래처 · 창고 · 품목/수량/단가 · 조정(할인) 항목 · 결제수단 (카드/현금, VAN 연동)

**기능**:
- Option > 금액조정항목설정에서 할인 품목을 1회 등록 후 계속 사용
- [조정] 버튼 클릭 > 등록한 할인 품목 선택 > 할인 금액을 마이너스(-)로 입력 → 하단 합계에 자동 반영, 할인 전/후 금액 모두 확인 가능
- 회계반영은 매출전표1로만, 건별 개별 처리 (기간합산 불가)
- 전표불러오기/웹자료올리기 불가 (판매입력Ⅰ과의 차이)
- 모바일 앱 입력 화면 설정 가능, PC와 동일한 방식 입력

**관련 보고서/출력물**: 판매현황, POS 매출 집계 (확인필요)


### 재고Ⅰ > 기타이동 > 창고이동

A창고에서 B창고로 재고를 옮기는 전표를 입력하는 메뉴. 총재고는 불변, 창고별 재고만 변동된다.

**주요 필드**: 일자 · 출고창고(보내는 창고) · 입고창고(받는 창고) · 품목 · 수량

**기능**:
- 창고 간 재고이동 기록 (예: 생산공장 → 불량창고로 불량품 이동)
- 요청/확인 프로세스: 창고관리자가 창고이동 요청을 확인하고 물건 이동 후 전표를 '확인' 처리해야 실제 이동 반영
- [생산입고1] 버튼 클릭 시 '생산전표생성' 체크박스 활성화 — 체크하면 보내는 창고의 원/부재료 차감 + 받는 창고에 완제품 입고(불출과 생산 동시 처리)
- 안전재고 이하 시 경고 대상 메뉴
- 시리얼/로트 품목은 이동 시 로트번호 지정

**관련 보고서/출력물**: 창고이동현황 (확인필요), 창고별재고현황, 재고수불부(이동입고/이동출고 구분 표시)


### 재고Ⅰ > 기타이동 > 자가사용

회사 내 자체사용, 무상 증여, 샘플 제공 등 판매 외 사유의 재고 출고를 처리하는 메뉴. 재고수량이 감소한다.

**주요 필드**: 일자 · 창고 · 품목 · 수량 · 사용사유/적요 (확인필요)

**기능**:
- 자체사용/무상증여/샘플제공 등 관리 — 저장 시 재고수량 감소
- 관계설정 품목은 대표품목(EA) 단위로 처리
- 안전재고 이하 시 경고 대상 메뉴
- 원가상세내역서에 자가사용 항목으로 집계되어 원가 반영

**관련 보고서/출력물**: 자가사용현황 (확인필요), 재고수불부, 원가상세내역서


### 재고Ⅰ > 기타이동 > 불량처리

재고자산의 불량 발생 시 처리·관리하는 메뉴. 저장 시 재고수량이 감소한다.

**주요 필드**: 일자 · 창고 · 품목 · 수량 · 처리방법 (폐기/정상사용/품목대체)

**기능**:
- 처리방법 3종: 폐기(재고 제거), 정상사용(정상 재고로 복원), 품목대체(다른 품목코드로 전환)
- 저장 시 재고수량 감소, 원가상세내역서에 불량처리 항목으로 집계
- 안전재고 이하 시 경고 대상 메뉴
- 불량창고를 별도 등록하고 창고이동과 조합하여 불량품 격리 운영 가능 (컨설팅 활용사례)

**관련 보고서/출력물**: 불량처리현황 (확인필요), 재고수불부, 원가상세내역서


### 재고Ⅰ > 기타이동 > 재고조정
*메뉴명: 재고조정 (재고실사)*

실물 재고조사(실사) 결과를 입력하고 장부재고를 실사재고로 강제 조정하는 메뉴. 초기세팅 시 기초재고 입력에도 사용된다.

**주요 필드**: 실사일자 · 창고 · 품목 · 장부수량(전산재고, 재고불러오기로 표시) · 실사수량(실제 카운트 수량) · 조정수량(차이, 자동계산) · 재고조정 반영 체크박스

**기능**:
- 2단계 구조: (1)실사 — 창고에서 실제 개수를 세어 입력, (2)조정 — 실사 결과를 장부에 반영. '실사 없이 조정만 할 수는 없음'
- [재고불러오기] 버튼으로 장부수량을 불러와 나란히 보면서 실사수량 입력
- 하단 '재고조정' 체크박스 체크 후 저장 시 실사와 동시에 조정 반영
- 간편재고조정: 실사+조정 두 단계를 모든 창고에 대해 한 번에 처리 (실사와 동시에 조정반영)
- 조정 대상 품목 선택 후 하단 조정 버튼 클릭 → 창고별 재고수량 입력 창에서 실사수량 입력·저장 시 조정 동시 반영
- 조정 결과는 재고현황/창고별재고현황에서 기준일자·창고 지정 조회로 확인
- 편집제한일자 설정(환경설정)으로 원가/재고 확정 월의 전표 수정 제한

**관련 보고서/출력물**: 재고실사현황 (실사 입력 내역 조회), 재고조정현황 (장부수량/실사수량/조정수량 동시 비교), 재고현황/창고별재고현황


### 재고Ⅰ > 출력물
*메뉴명: 출력물 (재고 보고서)*

재고현황, 재고수불부 등 재고 관련 각종 장부/보고서를 조회·출력하는 메뉴 그룹.

**주요 필드**: 조회기간/기준일자 · 창고 (전체/특정) · 품목/품목그룹 · 기타 옵션 (안전재고미만표시 등)

**기능**:
- 재고현황: 기준일자 시점의 품목별 재고수량 조회, 창고 지정 가능
- 창고별재고현황: 창고별 × 품목별 재고수량 매트릭스 조회
- 재고수불부: 일정기간 이동내역을 전기이월/입고/출고/현재고로 집계 — 입고는 매입·생산·이동입고로, 출고는 판매·반품·재고조정·이동출고 등으로 세분, 현재고 = 이월 + 입고 - 출고
- 재고변동표: 기간별 재고 변동 조회 (공식 메뉴별 영상으로 존재 확인)
- 집계표: 일별/월별/거래처별/품목별/담당자별/그룹별 집계
- 기타 옵션 > 안전재고미만표시: 안전재고 이하 품목을 붉은색으로 표시
- 관계설정 품목: 대표품목(EA) 환산 재고수량 또는 개별품목 수량 선택 표시
- 이익현황(판매이익) 조회
- 엑셀 다운로드/인쇄 양식설정 (확인필요)

**관련 보고서/출력물**: 재고현황, 창고별재고현황, 재고수불부, 재고변동표, 집계표(일별/월별/거래처별/품목별/담당자별/그룹별), 이익현황


### 재고Ⅱ > 시리얼/로트No.

품목별로 시리얼번호(개별 1개) 또는 로트번호(배치 단위)를 부여하여 입고부터 출고, A/S까지 개체 단위 이력을 관리하는 메뉴 그룹.

**주요 필드**: 시리얼/로트No. · 품목코드 · 필수입력여부 (필수입력/선택입력 — 일부 품목만 관리 시 선택입력) · 입력수량형식 (로트No. 관리 시 '수량입력 제한없음' 선택) · 창고별사용여부 (시리얼/로트 재고수량을 창고별로 관리 시 '사용' 체크) · 유통기한 (시리얼/로트No. 항목으로 추가 입력 가능)

**기능**:
- 기초설정: 재고Ⅱ > 시리얼/로트No. 기초설정에서 필수입력여부/입력수량형식/창고별사용여부 설정
- 품목별 사용여부: 재고Ⅰ > 기초등록 > 품목등록 > 품목코드 클릭 > 관리대상 탭 > 시리얼/로트 설정
- 시리얼/로트No.등록: 번호 등록 및 [라벨인쇄] — 품목 체크 후 [바코드인쇄] > 우측상단 [양식] 선택(기본 ecount229:B4, ecount247 등으로 변경 가능)
- 재고전표(구매/생산입고/판매/소모 등) 입력 시 시리얼 [선택] 버튼으로 시리얼/로트 선택 후 수량 입력
- 출고 이후 A/S 전표에서도 시리얼/로트No. 입력 가능 — 품목별 사용현황·이력관리·전표추적
- 시리얼번호는 품목 바코드와 별개로 바코드로 인식되어 개체 단위 스캔 관리 — 하나의 품목코드에 다수 시리얼 생성, 시리얼별 바코드 생성
- 원가는 품목코드 기준이므로 시리얼/로트별 원가관리가 필요하면 품목코드에 시리얼/로트를 포함해 등록하는 우회 방식 사용 (컨설팅 사례)
- 유통기한을 로트 속성으로 입력하여 선입선출/기한 관리 (확인필요: 자동 경고 기능)

**관련 보고서/출력물**: 시리얼/로트No.재고현황 (시리얼/로트별 × 창고별 재고수량), 시리얼/로트No.재고수불부 (입고~출고 상세이력), 시리얼/로트No.사용현황/이력조회 (전표추적)


### 재고Ⅱ > WMS
*메뉴명: WMS (창고관리/위치관리)*

창고 내 위치(Location, 랙)와 Lot 단위까지 세분화하여 입출고를 관리하는 창고관리시스템. '창고(WMS)'와 '장부(ERP 재고수불부)'가 별도로 움직이며 ERP 전표생성으로 연동된다.

**주요 필드**: 위치(랙) 코드 · 입고예정수량 · 입고지시 위치 · 출고예정 (일자/거래처/품목) · Lot 번호

**기능**:
- 프로세스 4단계: (1)입고예정등록 — 재고수량 미반영, '입고예정수량'으로만 표시 (2)입고지시/입고처리 — 실물 도착 시 예정 건 선택 후 [입고지시]로 보관 위치 확정 (3)출고예정 — 판매 일자/거래처/품목 입력 (4)출고지시 — 선입선출 기준으로 나갈 Lot 번호 자동 추천
- 입고처리 완료해도 재고수불부에는 미반영 — 처리 내역 선택 후 [ERP 전표생성] 버튼으로 '구매입력' 전표 저장 시 비로소 장부 재고 증가 (WMS-ERP 연동의 핵심 단계)
- 위치별 재고 시각화: 랙별 재고 위치를 그림으로 표시하는 매크로 제공 — 창고 구조에 따라 각 랙의 품목을 한눈에 확인
- 재고 위치 등록 및 드래그 앤 드롭 또는 바코드 스캔으로 위치 간 재고이동
- WMS 내 재고조정 및 출력물 메뉴 (공식 메뉴별 영상으로 존재 확인)
- 모바일 앱 바코드 스캔으로 실시간 위치/재고 추적

**관련 보고서/출력물**: 위치별재고현황, 입고예정현황/출고예정현황 (확인필요), WMS 출력물


### 재고Ⅱ > 바코드 (및 품목등록 바코드 항목)
*메뉴명: 바코드 관리 (발행/스캔 입출고)*

품목·시리얼 바코드의 생성/인쇄와 바코드 스캐너·모바일 카메라를 이용한 입출고 전표 입력을 지원한다.

**주요 필드**: 바코드 번호 (품목등록 바코드 항목) · 바코드 형식 · 라벨 양식 · 바코드 크기/여백 · 라벨 표시항목 (품목명/규격/단가 등)

- 저장/전표 버튼에 마우스 오버 시 전자(세금)계산서발행 버튼 표시 → 국세청(홈택스) 연동 발행
- 반품 처리: 수량을 마이너스로 입력(단가는 판매 당시 금액)하거나 기존 판매전표 하단 [반품처리] 버튼 클릭 → 재고수량 증가. 판매전표의 변경가능 항목: 프로젝트, 담당자, 창고, 품목, 수량, 단가, 적요 / 회계반영 후 변경불가 항목: 거래처, 공급가액 합계, 부가세 합계
- 무형상품 품목을 이용해 택배비·할인 등을 거래명세서/견적서에 표시 가능
- 엑셀 자료올리기/웹자료올리기, Open API(SaveSale: IO_DATE, CUST, WH_CD, PROD_CD, PROD_DES, QTY 등 필드)로 외부 시스템 연동 입력
- 모바일 앱에서 PC와 동일하게 판매전표 생성 및 ERP 전송 가능

**관련 보고서/출력물**: 판매조회(거래명세서 출력/메일/팩스/PDF), 판매현황, 미판매현황, 거래처별채권, 매입매출장, 집계표


### 재고Ⅰ > 영업관리 > 판매 > 판매입력Ⅱ
*메뉴명: 판매입력Ⅱ (POS형 판매입력)*

오프라인 매장·POS 기반 소매 판매에 최적화된 판매입력 화면. 카드단말기(VAN) 연동 결제와 할인 처리를 지원하며 추가 비용 없이 사용 가능.

**주요 필드**: 일자 · 거래처(소매/일반 고객) · 품목(바코드 스캔 가능 (확인필요)) · 수량 · 단가 · 할인(금액조정항목) · 결제수단(현금/카드)

**기능**:
- 이카운트 POS 전용 입력 화면 (카드단말기/VAN 연동 필요), ERP 사용 중이면 추가 계약 없이 POS 기능 사용 가능
- 할인 처리: 금액조정항목설정에서 1회 설정 후 계속 사용 (판매입력Ⅰ은 품목등록에 할인품목을 직접 추가하는 방식과 대비됨)
- 할인가 적용 방법 변경 업그레이드 이력 존재 (공식 업그레이드 노트)
- 다양한 결제방식 지원 (현금/카드 등, POS 결제)
- POS 결제내역자료비교 기능으로 카드 결제내역과 판매자료 대사 가능
- 모바일 앱에서 판매입력Ⅱ 사용 가능 (PC와 거의 동일한 입력 방식)
- 소매매출(사업자가 아닌 개인 대상 현금매출, 세금계산서 미발행) 처리에 활용

**관련 보고서/출력물**: 판매현황, POS 결제내역자료비교


### 재고Ⅰ > 영업관리 > 판매 > 판매조회 (거래명세서 출력)
*메뉴명: 거래명세서 발행 (판매조회 내 기능)*

판매입력과 동시에 자동 생성되는 거래명세서를 출력·전송하는 기능. 별도 작성 없이 판매전표에서 바로 발행한다.

**주요 필드**: 공급자 정보(사업자번호/상호/대표자/주소/업태/종목) · 공급받는자 정보 · 일자 · 품목명/규격 · 수량 · 단가 · 공급가액 · 세액 · 합계금액 · 인수자 서명란 (확인필요)

**기능**:
- 판매입력 시 거래명세서 자동 생성 (공식 제품 페이지 '거래명세서 자동 생성')
- 판매조회에서 거래명세서 출력 / 이메일 발송 / 팩스 발송 / PDF 변환 가능 (공식 초급교재 확인)
- 이메일 발송 시 재고전표와 연결된 거래명세서를 첨부하여 발송, 발신자를 사용자의 웹메일 계정으로 지정 가능
- 이메일 발송 화면 상단 Option > 메일수신화면양식에서 수신 화면 양식 변경 가능 (웹거래명세서 형태의 수신 화면)
- 양식설정: 회사 로고·인감 삽입, 항목 추가/배치 변경, 보고서당 최대 50개 양식 저장, 공급자/공급받는자 보관용 2매 출력 (확인필요: 2매 옵션 명칭)
- 거래처관리대장(출력물)에서도 거래명세서 인쇄 가능 — 수량/단가/판매금액/수금/잔액을 원하는 형태로 표시
- 납기일자, 품명, 수량, 단가 등이 거래명세서에 표시됨
- 무형상품 라인으로 택배비·할인·에누리 표시 가능
- SMS/카카오톡 알림톡 전송 (확인필요: 카카오톡 지원 여부)

**관련 보고서/출력물**: 거래명세서(인쇄/PDF/이메일/팩스), 거래처관리대장


### 재고Ⅰ > 영업관리 > 판매 > 판매현황

판매입력한 내역을 다양한 조건으로 조회·집계하는 장부 화면. 거래처별/품목별/담당자별/기간별 매출 분석의 중심 메뉴.

**주요 필드**: 일자 · 전표번호 · 거래처 · 품목 · 수량 · 단가 · 공급가액 · 부가세 · 합계 · 담당자 · 창고 · 적요 · 프로젝트

**기능**:
- 검색조건: 기간(일자), 거래처, 품목, 담당자, 창고 등 다중 조건 검색
- 비교기간별 집계: 여러 창을 띄우지 않고 월별 등 기간을 나란히 비교
- 조건양식(검색어 저장) 설정: 사용자별 기본 검색 양식을 저장해 진입 시 자동 적용
- 항목별 정렬/필터 설정: 현황 화면에서 직접 컬럼별 필터·정렬·양식 수정 (업그레이드로 현황메뉴에서 직접 수정 가능)
- 소계 표시 설정 (거래처별/품목별 소계 등)
- Option > 자동알림설정: 판매현황을 매일 수동 발송하는 대신 지정 대상에게 자동 발송
- 현황 메뉴 이력관리(수정 이력) 업그레이드 존재
- 엑셀 다운로드 (권한 설정으로 통제 가능), 인쇄
- 실시간 집계: 판매 입력 즉시 매출·채권 보고서에 반영 (경영진 실시간 조회)

**관련 보고서/출력물**: 집계표(재고Ⅰ > 출력물 > 집계표: 일별/월별/거래처별/품목별/담당자별/그룹별 집계), 거래처출고현황, 매입매출장, 품목별 판매순위 (확인필요)


### 재고Ⅰ > 영업관리 > 수금 > 수금입력

판매(외상매출)로 발생한 미수금에 대해 거래처로부터 받은 수금 내역을 입력하는 메뉴. 입력 즉시 거래처별 채권 잔액이 차감된다.

**주요 필드**: 일자 · 거래처 · 수금구분(현금/예금/받을어음 등) · 금액 · 담당자 · 적요 · 프로젝트 (확인필요)

**기능**:
- 거래처별 미수금 잔액을 확인하면서 입금(수금) 내역 기록
- 입력 필드: 월/일(거래일자), 구분(수금 유형), 거래처, 금액, 적요
- 수금구분: 현금/보통예금/받을어음 등 — 받을어음은 받을어음장에서 '입금' 구분 거래로 결제 처리 (정확한 구분값 목록 (확인필요))
- 선수금 처리 지원 (확인필요: 별도 구분 존재 여부)
- 회계모듈 입금전표와의 연동(회계반영) — 재고 수금입력과 회계 입금전표 이중 입력 방지 구조 (확인필요: 연동 옵션)
- 은행 거래내역 자동수집(은행연동)으로 입금 내역을 불러와 수금 처리 가능 (확인필요: 재고 수금과의 직접 연결)
- 수금 입력 즉시 거래처별채권·미수금 현황에서 잔액 자동 차감

**관련 보고서/출력물**: 수금현황, 거래처별채권(채무), 월별채권증감내역, 거래처관리대장


### 재고Ⅰ > 출력물 > 거래처별채권(채무) 외
*메뉴명: 미수금 현황 / 채권관리 (거래처별채권)*

판매·수금 입력 결과가 자동 집계되는 채권(미수금) 장부군. 거래처별 미수 잔액과 월별 증감을 추적하고 미수금 독촉까지 지원한다.

**주요 필드**: 거래처 · 전기이월(기초잔액) · 매출(재고매출/회계매출) · 수금 · 잔액 · 기간

**기능**:
- 거래처별채권: 거래처별 미수금 잔액 확인. '재고매출' 컬럼에는 재고Ⅰ>영업관리>판매입력 값이 표시되며 회계반영을 해도 해당 컬럼 값 유지
- 월별채권증감내역: 거래처별 > 월별로 매출/수금/잔액 증감 확인
- 거래처관리대장: 거래처별 거래내역(수량/단가/판매금액/수금/잔액)을 원하는 양식으로 출력, 거래명세서 인쇄 가능 — 청구서(대금청구서) 용도로 활용
- 미수금 회수 관리: 채권잔액이 있는 거래처 리스트에 미수금 요청 문자를 일괄 발송하는 버튼 제공
- 잔액재집계: 과거 일자 전표가 최근 입력된 경우 월별 잔액장부를 최신 잔액으로 재계산 — 조회 전 재집계 권장
- 채권/채무 잔액 조정 기능 (기초잔액 등록/조정)
- 판매입력만 해도 재고 채권장부에 자동 반영, 회계반영 시 회계 채권(외상매출금) 장부와 연결
- 입력 내역은 매입매출장, 자금일보, 거래처별 채권/채무, 거래처 관리대장 등 회계장부에 자동 반영
- 미수금 상세: 채권 기산일·회수예정일 관리 (확인필요)

**관련 보고서/출력물**: 거래처별채권(채무)현황, 월별채권증감내역, 거래처관리대장(청구서), 자금일보, 매입매출장


### 재고Ⅰ > 기초등록 > 단가관리 > 특별단가등록
*메뉴명: 단가관리 / 판매단가 적용 (특별단가등록)*

품목 기본단가 외에 거래처별·그룹별 단가표를 만들어 판매입력 시 자동 적용하는 체계. 견적/주문/판매 입력 시 단가가 자동으로 채워진다.

**주요 필드**: 단가표코드(특별단가그룹) · 적용 거래처 · 품목코드 · 단가 · 적용기간 (확인필요) · 할인율 (확인필요)

**기능**:
- 품목등록에 기본 입고단가/출고단가(판매단가) 등록 — 단가 레벨(단가 A~J 등 다중 단가) 존재 여부 (확인필요)
- 특별단가등록: [재고Ⅰ] > [기초등록] > [단가관리] > [특별단가등록]에서 단가표 코드 등록 → [품목별] 탭에서 품목별 단가 설정
- 특별단가그룹 탭에서 신규 그룹 생성 → [거래처설정] 클릭 후 추가 버튼으로 거래처 연결 → [품목설정]에서 품목별 단가 지정 (싸부넷 FAQ 확인)
- 거래처특별단가그룹등록: 거래처마다 단가표(단가그룹)를 연결하여 거래처별 차등 단가 적용
- 거래처별/창고별/그룹별 단가표 구성 가능
- 거래처를 그룹으로 분류하여 그룹별 단가 지정 가능 (공식 단가관리 페이지)
- 판매입력 시 거래처+품목 조합으로 단가 자동 적용 — 적용 우선순위(특별단가 > 거래처단가 > 품목 기본단가 > 최근 판매단가)의 정확한 순서 (확인필요)
- 최근 거래단가 불러오기 기능 (확인필요)
- 할인율/할인가 적용: 판매입력Ⅱ는 금액조정항목, 판매입력Ⅰ은 할인 품목 방식

**관련 보고서/출력물**: 품목별 단가 조회, 특별단가 등록 현황 (확인필요)


### 재고Ⅰ > 영업관리 (견적서 → 주문서 → 판매) + 미주문현황/미판매현황
*메뉴명: 견적→주문→판매 전환 흐름 (끌어오기/진행관리)*

이전 단계 전표를 [주문] 등 불러오기 버튼으로 끌어와 다음 단계 전표를 생성하는 단계별 진행 구조. 각 단계의 미진행 잔량이 자동 관리된다.

**주요 필드**: 원전표 번호(견적/주문 참조) · 진행상태(진행중/완료) · 주문수량 · 판매(출고)수량 · 잔량

**기능**:
- 업무 흐름: 견적서 → 주문서 → (출하지시서 → 출하) → 판매(거래명세서) → 수금 (출하 단계는 선택 사용)
- 주문서입력에서 견적서를 불러와 입력하면 미주문(견적 후 미수주) 건 관리 가능 (likewind 위키/공식 교재 교차 확인)
- 판매입력에서 [주문] 버튼으로 주문서를 불러와 입력하면 미판매현황 관리 가능
- 미주문현황: 견적서는 입력됐으나 아직 주문으로 진행되지 않은 건 조회

- 주문 오더 중심 진행상황 관리: 수주→출하까지 흐름도(플로우) 형태로 추적 (공식 재고 주문관리 페이지)

**관련 보고서/출력물**: 미주문현황, 미판매현황, 주문진행현황, 미출하현황

### 재고Ⅰ > 영업관리 > 판매 (마이너스 입력 / 반품처리 버튼)

판매 반품은 별도 메뉴가 아니라 판매입력의 마이너스 수량 입력 또는 기존 판매전표의 반품처리 버튼으로 처리한다. 처리 시 재고가 증가하고 채권이 차감된다.

### 판매입력/판매조회 [+]버튼 · 판매일괄회계반영 · 회계Ⅰ > 매출전표
*메뉴명: 회계반영 / 전자세금계산서 연계 (영업 프로세스 마감)*

판매전표를 매출전표로 연결(분개 처리)하고 전자세금계산서를 발행하는 영업-회계 연동 기능.

**기능**:
- 회계반영 = 판매입력한 거래내역을 분개처리/세금계산서 작성으로 연결하는 작업 (세금계산서 발행 준비)

- 회계반영 후에는 거래처, 공급가액 합계, 부가세 합계 변경 불가 (프로젝트/담당자/창고/품목/수량/단가/적요는 변경 가능)

## 구매관리 (재고Ⅰ > 구매관리, ECOUNT ERP 5.0)

> **화면 특징**: 이카운트 전표 입력화면은 공통적으로 '상단(헤더) + 하단(품목 라인 그리드)' 2단 구조. 상단에 일자-No.(전표번호 자동채번), 거래처, 창고, 담당자, 부가세율 등을 입력하고 하단 그리드에 품목코드(F2 코드도움 팝업), 품목명/규격, 수량, 단가, 공급가액, 부가세, 적요를 라인 단위로 입력. 우측 상단 [Option] 버튼에 입력화면설정(항목 추가/삭제, 입력순서 지정 — Enter 키로 다음 순서 필드 이동, 일괄설정)과 매핑설정(전 단계 전표 항목을 다음 전표 항목으로 전달)이 있음. 상단 기능버튼 영역에 끌어오기 버튼([발주요청], [소요], [주문], [발주] 등)이 있어 이전 단계 전표를 팝업(예: 발주서조회 — 접수/발주중/완료 탭)에서 검색·선택해 불러오는 방식이 핵심 UX. 발주요청·발주계획 등 내부용 전표는 거래처 필드가 하단 라인에 위치하고, 발주서·구매 등 외부 거래 전표는 거래처가 상단에 위치. 진행상태(접수→발주중→완료)는 전표 하단 체크박스+선택으로 변경. 모든 현황(보고서) 화면은 검색조건 패널 + 결과 그리드 구조이며 일별/월별/거래처별/품목별/담당자별 집계 전환, EXCEL 변환, 인쇄 양식설정(회사 로고·항목 배치 커스터마이징), 웹자보 출력을 공통 지원. 재고 전표(구매입력)는 저장 즉시 재고수량·거래처 채무에 반영되고, [회계반영]/[일괄회계반영] 버튼으로 회계전표(외상매입금 자동분개)를 생성하는 '재고→회계 2단계 반영' 구조가 특징.


### 재고Ⅰ > 구매관리 > 발주요청입력
*메뉴명: 발주요청입력 (구매요청)*

현업/타부서가 필요한 자재의 구매(발주)를 구매부서에 요청하는 입력 메뉴. 이카운트 구매 프로세스의 시작 단계(발주요청→발주계획→발주서→구매).

**주요 필드**: 일자-No. · 요청 담당자/부서 · 품목코드(F2 코드도움) · 품목명/규격 · 수량 · 납기(요청)일자 · 거래처(라인 단위, 선택) · 적요

**기능**:
- 타부서(현업) 담당자가 필요 품목·수량을 요청 전표로 입력
- 발주계획입력 화면의 [발주요청] 버튼으로 요청 내역을 끌어와 연계 처리
- 외부 발송용이 아닌 내부용 전표이므로 거래처 필드가 화면 하단(품목 라인 영역)에 위치 — 거래처별로 나눠 작성할 필요 없음
- 요청 내역은 발주요청현황에서 조회 (집계표 기본 양식 제공 — 공식 업그레이드 공지로 확인)
- 요청 승인/처리 워크플로우(그룹웨어 결재 연동) (확인필요)

**관련 보고서/출력물**: 발주요청현황 (집계표 양식 포함)


### 재고Ⅰ > 구매관리 > 발주계획입력

구매부서가 발주서를 만들기 전 내부적으로 발주 수량을 계획·확정하는 메뉴. 발주요청 수량 확인, 주문제작용 원부자재 소요 산출에 사용.

**주요 필드**: 일자-No. · 담당자 · 품목코드 · 수량(계획수량) · 납기일자 · 거래처(라인 단위) · 적요

**기능**:
- [발주요청] 버튼으로 발주요청 내역 끌어오기
- [소요] 버튼으로 소요량(BOM 기반 원부자재 소요) 끌어오기 — 주문받은 제품 생산에 필요한 원부자재 발주 준비
- 필요수량 자동 계산: 안전재고, 보유재고(현재고), 미판매수량, 미불출수량, 미입고수량, 최소구매단위를 고려하여 적정 발주수량 자동 산정 (공식 업그레이드 공지로 확인)
- 자재소요계획(MRP)과 연계하여 발주수량과 입고 필요 시기 계산
- 품목등록의 수량 탭에서 설정한 최소구매단위·주거래처(주로 구매하는 거래처)를 활용
- 내부 계획용이므로 거래처 필드가 하단(품목 라인)에 위치
- 발주계획조회에서 발주 리스트 확인 후 발주서 일괄 생성 — 거래처별/납기일자별/품목별 발주서 일괄생성
- 각 거래처 담당자에게 견적요청서를 E-mail로 일괄 발송하고, 선정된 단가를 발주서에 그대로 적용하는 단가견적 비교 기능

**관련 보고서/출력물**: 발주계획조회(발주리스트), 자재소요계획(MRP) 연계 현황


### 재고Ⅰ > 구매관리 > 발주서입력

구매처에 물품 구매를 요청(발주)하는 발주서를 작성하는 메뉴. 직접입력하거나 판매주문·발주계획·작업지시 데이터를 끌어와 자동작성.

**주요 필드**: 발주일자-No. · 구매처(거래처) · 담당자 · 입고창고 · 품목코드(F2) · 품목명/규격 · 수량 · 단가 · 공급가액 · 부가세 · 납기일자(품목별 추가 가능) · 적요 · 진행상태(접수/발주중/완료)

**기능**:
- 직접입력 또는 끌어오기: 판매주문(주문서), 발주계획, 작업지시서 내역을 로드하여 발주서 생성 — 중복 입력 제거
- 발주서 진행상태 관리: 접수 → 발주중 → 완료 3단계 (완료 = 거래처 승인·납기 확정 상태), 전표 하단 '발주서 진행상태변경' 체크로 상태 변경
- 품목별 납기일자 입력: 우측상단 [Option] > [입력화면설정] > [기본:발주서입력] > 항목 [추가] > [납기일자] 추가 시 한 발주서 내 품목별 납기요청일 개별 관리
- 발주서 인쇄(양식설정으로 회사 전용 양식 커스터마이징), E-Mail 전송, 수정/삭제
- 발주서가 온라인수발주시스템(C-Portal)에 반영되어 거래처(공급처)가 온라인으로 발주 내역 확인
- 구매입력에서 [발주] 버튼으로 불러와 입고(구매) 처리 — 발주 대비 잔량(미입고) 자동 관리
- Option > 매핑설정: 발주서의 품목코드 등 항목을 구매입력의 적요 등 원하는 항목으로 매핑하여 전달
- 입력화면설정: 항목 추가/제거, 입력순서 지정(Enter로 다음 필드 이동), 일괄설정
- 발주 입력 기본 흐름: ① 발주품목·구매처 입력 → ② 발주수량 확정 → ③ 발주서 등록 → ④ 구매(입고)처리

**관련 보고서/출력물**: 발주서조회(접수/발주중/완료 탭), 발주현황, 발주미입고현황(발주 대비 미입고 수량 보고서)


### 재고Ⅰ > 구매관리 > 구매입력

실제 물품 입고(구매) 거래를 입력하는 메뉴. 저장 시 재고수량이 자동 증가하고 거래처별 채무(미지급금)에 자동 반영됨.

**주요 필드**: 일자-No. · 구매처(거래처) · 입고창고 · 담당자 · 부가세율(별도/포함) · 품목코드(F2) · 품목명/규격 · 수량 · 단가 · 공급가액 · 부가세 · 적요 · 프로젝트

**기능**:
- [발주] 버튼으로 발주서 끌어오기: '발주서조회' 팝업에서 접수/발주중/완료 탭으로 발주서 검색 → 대상 선택 → 재고수량 확인 후 '입력수량' 입력(부분입고 가능) → 하단 '발주서 진행상태변경' 체크(완료 선택) 후 저장
- 발주 없이 직접입력도 가능
- 부분구매(분할 입고) 지원: 발주 잔량은 미입고(미구매)현황으로 자동 추적
- 저장 시 재고수량 자동 증가, 실시간 재고 장부 반영
- 구매금액이 거래처별 채무(미지급금)에 자동 반영 — 회계처리 전이라도 판매/구매입력만으로 채권/채무 잔액에 반영
- [회계반영](건별) / [일괄회계반영](기간 합산) 버튼으로 회계 매입전표 생성 — 매입전표는 외상매입금 계정 기본 사용, 자동분개
- 반품(구매취소): 수량을 마이너스(-)로 입력하여 구매처 반출 처리, 또는 불량처리입력에서 폐기 처리; 기존 전표의 반품처리 버튼 사용 (판매전표에서 확인됨, 구매전표 동일 여부 확인필요)
- Option > 입력화면설정: 항목 추가/삭제, 입력순서 설정(Enter 이동), 일괄설정
- Option > 매핑설정: 발주서 항목(품목코드 등)을 구매입력 적요란에 자동 기재
- 엑셀 웹업로드로 대량 구매전표 등록(기존 프로그램 데이터 이관 포함)
- 단가 자동 적용: 품목별/거래처별 등록 단가 및 단가표 적용, 단가를 공급가액과 부가세로 자동 분리
- 외화 구매: 통화/환율 입력 (확인필요)
- 구매입력Ⅱ(간이 화면) 존재 여부 (확인필요 — 판매입력Ⅱ는 확인됨)

**관련 보고서/출력물**: 구매조회, 구매현황, 미구매(미입고)현황, 재고현황/창고별재고현황(자동 반영), 매입매출장·자금일보·거래처별 채권/채무·거래처 관리대장(회계반영 시)


### 재고Ⅰ > 구매관리 > 구매현황 (출력물: 재고Ⅰ > 출력물)
*메뉴명: 구매현황 / 구매조회*

구매입력된 내역을 다양한 기준으로 조회·집계하는 보고서 메뉴.

**주요 필드**: 조회기간 · 거래처 · 품목 · 창고 · 담당자 · 프로젝트

**기능**:
- 기간·거래처·품목·창고·담당자 등 검색조건으로 구매내역 조회
- 집계표: 일별/월별/거래처별/품목별/담당자별/그룹별 집계
- 구매현황, 부분주문(부분구매), 안전재고 등 다양한 구매 관련 보고서 작성 가능 (공식 기능소개 확인)
- 모든 출력물은 EXCEL 변환 및 양식설정으로 회사 전용 현황 커스터마이징 가능
- 재고Ⅰ > 출력물 > 회계미반영현황(판매/구매): 회계반영 안 된 구매 건 확인

**관련 보고서/출력물**: 구매현황(거래처별/품목별/일별/월별/담당자별 집계), 회계미반영현황(판매/구매), 이익현황(품목별 매출·원가·이익)


### 재고Ⅰ > 구매관리 > 발주현황 · 미입고현황 (정확한 메뉴명 확인필요)
*메뉴명: 발주현황 / 발주미입고현황*

발주 진행 상황과 발주 대비 미입고 수량을 보고서로 확인하는 메뉴.

**주요 필드**: 조회기간 · 거래처 · 품목 · 진행상태

**기능**:
- 발주 대비 미입고 수량을 보고서 형태로 확인 — 구매 진행상황 즉시 파악 (공식 기능소개 확인)
- 발주서 진행상태(접수/발주중/완료)별 리스트 조회
- 미입고 관리는 품목코드 기준으로 수행
- 미입고 잔량을 구매입력으로 끌어와 후속 입고 처리

**관련 보고서/출력물**: 발주현황, 미입고(미구매)현황, 발주요청현황


### 재고Ⅰ > 구매관리 내 현황 + 회계Ⅰ > 장부 (정확한 메뉴명 확인필요)
*메뉴명: 구매미지급현황 (미지급금 관리)*

구매입력으로 자동 발생한 거래처별 채무(미지급금)와 지급액·잔액을 조회하는 현황.

**주요 필드**: 조회기간 · 거래처 · 담당자

**기능**:
- 구매금액이 거래처별 채무에 자동 반영 — 회계처리 없이 구매입력만으로 채무 잔액 계상
- 미지급 장부: 담당자별/거래처별 미지급 금액·지급 금액·잔액을 한눈에 확인 (공식 기능소개 확인)
- 거래처별채권(채무) 장부: 조회기간 동안 매입/지급/잔액을 거래처별 확인
- 거래처별채권(채무) 메뉴 Option의 '미청구채권(채무) 재집계' 기능으로 잔액 조정, 미청구채무 잔액 별도 변경 기능 존재 (중원컨설팅 확인)
- 회계반영 시 매입매출장, 자금일보, 거래처 관리대장 등 회계장부에 연동

**관련 보고서/출력물**: 미지급 장부(거래처별/담당자별), 거래처별채권(채무), 거래처 관리대장, 자금일보


### 메뉴 위치 (확인필요 — 구매관리 하위 또는 회계 매출매입거래 하위)
*메뉴명: 지불입력*

구매처에 대한 대금 지급을 입력하여 미지급금(채무)을 차감하는 메뉴. 공개 소스에서 화면 상세는 확인되지 않음.

**주요 필드**: 지급일자 · 거래처 · 지급금액 · 지급계좌/지급방법 · 적요 (모두 확인필요)

**기능**:
- 지급 내역 입력 시 거래처별 채무 잔액 차감 (확인필요)
- 은행연동으로 수집된 입/출금 내역을 회계전표로 저장·장부 반영 가능 (공식 기능소개 확인)
- 매입전표Ⅰ(회계Ⅰ > 매출매입거래 > 매입전표Ⅰ): 외상매입금 계정 기본 사용, 상황에 맞는 회계계정 선택 가능 — 지급 처리와 연계
- 회계Ⅱ 자금계획: 캘린더/표 형태로 거래처별 지급 예정 일자 관리 (매입/매출 자금계획)
- 수금입력(판매측 대응 메뉴)과 대칭 구조 (확인필요)

**관련 보고서/출력물**: 미지급 장부, 거래처별채권(채무), 자금계획(회계Ⅱ), 자금일보


### 재고Ⅰ > 구매관리 > 구매입력 (마이너스 입력) / 재고Ⅱ > 불량처리입력
*메뉴명: 반품(구매취소) 처리*

구매한 물품을 구매처로 반출(반품)하거나 폐기하는 처리. 별도 '구매반품' 메뉴가 아닌 구매입력의 음수 입력 방식.

**주요 필드**: 일자 · 거래처 · 품목 · 수량(음수) · 단가 · 적요

**기능**:
- 구매입력에서 수량을 마이너스(-)로 입력하여 구매처 반출 처리 — 재고 감소, 채무 차감 (공식 교재·기능소개 확인)
- 단가는 구매 당시 금액으로 입력 (판매 반품 기준 확인, 구매 동일 적용 추정)
- 불량처리입력에서 폐기 처리 옵션 (구매처 반출 대신 자체 폐기)
- 기존 전표 하단 반품처리 버튼 (판매전표 확인됨, 구매전표 지원 여부 확인필요)
- 반품 내역은 구매현황에 음수 라인으로 집계 (확인필요)

**관련 보고서/출력물**: 구매현황, 재고수불부, 거래처별채권(채무)


### 회계Ⅱ > 수입비용
*메뉴명: 수입비용 (수입제비용)*

해외 수입 건에 대한 물품대금과 부대비용을 인보이스/BL 단위로 집계하고 품목 원가에 배부하는 메뉴.

**주요 필드**: BL No./인보이스 번호 · 거래처 · 비용항목(운송비/관세/하역비 등) · 금액 · 배부기준 (확인필요)

**기능**:
- 인보이스(BL No.)별로 부대비용 항목(운송비/관세/하역비/통관수수료 등)별 금액 등록 (중원컨설팅·공식 기능소개 교차 확인)
- 관세사 정산서 등 여러 장의 영수증을 하나의 수입 건(BL No. 기준)으로 묶어 클릭 한 번으로 물품 원가에 배부 (공식 기능소개 확인)
- 수입 건별 물품대금·비용 집계 및 상세내역 조회 기준으로 활용
- 부대비용을 각 품목별 원가(취득원가)에 반영 가능 — CIF 과세가격 + 관세 + 부대비용 = 취득원가 산출
- 수입비용관리대장에서 인보이스별·비용항목별 금액 확인
- 외화 구매입력과의 연계(환율 적용) (확인필요)

**관련 보고서/출력물**: 수입비용관리대장, 품목별 원가 반영 현황


### 재고Ⅰ > 기초등록 > 품목등록 (수량 탭) + 발주계획 연계
*메뉴명: 안전재고/발주점 관리*

품목별 안전재고와 최소구매단위를 등록해 발주 필요수량을 자동 산출하는 재주문점 관리 기능.

**주요 필드**: 품목코드 · 안전재고수량(전사/창고별) · 최소구매단위 · 주거래처

**기능**:
- 품목등록 > 수량 탭에서 안전재고수량 입력 (창고별 안전재고 등록 가능)
- 품목등록 > 수량 탭에서 최소구매단위, 주로 구매하는 거래처(주거래처) 설정 — 발주계획에서 활용
- 필요수량 자동 계산: 안전재고, 보유재고, 미판매, 미불출, 미입고, 최소구매단위 고려 (공식 업그레이드 공지 확인)
- 안전재고 보고서로 부족 품목 확인 후 발주계획→발주서 생성
- 재고부족 알림 기능 (확인필요)
- MRP(자재소요계획)와 연계한 발주수량·입고시기 계산

**관련 보고서/출력물**: 안전재고 현황(부족수량), 재고현황/창고별재고현황, 발주계획조회


### 재고Ⅰ > 기초등록 > 단가관리 (품목등록 단가 항목 포함)
*메뉴명: 단가관리 (구매단가)*

품목별·거래처별 구매/판매 단가를 등록하고 전표 입력 시 자동 적용하는 단가 체계 관리.

**주요 필드**: 품목코드 · 거래처/거래처그룹 · 단가(입고/출고) · 적용기간 (확인필요) · 단가표 구분

**기능**:
- 품목별 기본 단가(입고단가/출고단가) 등록
- 거래처별·공급업체별 단가 등록 — 같은 품목이라도 구매처마다 다른 단가 적용 (공식 기능소개 확인)
- 거래처별/창고별/그룹별 단가표 생성·적용, 거래처를 그룹으로 분류하여 단가 차등 적용
- 특별단가등록 기능
- 단가 이력 관리: 이카운트 설계 보고서로 단가 변경 이력 조회
- 등록된 품목 정보 일괄변경 지원 (품목코드는 일괄변경 불가)
- 전표 입력 시 단가를 공급가액/부가세로 자동 분리
- 단가 적용 우선순위(거래처별 > 단가그룹 > 품목 기본단가 등) 세부 규칙 (확인필요)
- 최근 구매단가 자동 제안 (확인필요)

**관련 보고서/출력물**: 단가 이력 보고서, 거래처별 단가표


### 자사몰/포털 설정 (재고 > 온라인수발주) — 발주서입력과 연동
*메뉴명: 온라인수발주시스템 (C-Portal, 발주 연계)*

ERP에서 작성한 발주서를 거래처(공급처)가 온라인 포털에서 직접 확인하고, 거래처가 주문을 직접 등록할 수 있는 부가 시스템.

**주요 필드**: 거래처 계정 · 품목 · 수량 · 납기

**기능**:
- ERP에서 작성한 발주서가 온라인수발주시스템에 반영되어 공급처가 발주 내역 확인 (공식 기능소개 확인)
- 거래처가 직접 온라인으로 주문 등록, 실시간 주문 접수
- 거래처/대리점/지점별 관리
- 모바일 앱(이카운트 C-Portal)으로 주문 작성 지원
- 거래처가 명세서(인보이스)·주문 정보 실시간 조회

**관련 보고서/출력물**: 주문 접수 현황


## 생산관리 (이카운트 ERP 5.0 — 재고Ⅰ [생산/외주] + 재고Ⅱ [계획관리/이익관리] 중심)

> **화면 특징**: 이카운트 ERP 5.0 생산관리는 별도 '생산' 탭이 아니라 재고 모듈에 통합되어 있음: 수불이 발생하는 전표(작업지시서/생산불출/생산입고1·2·3/불량처리)는 [재고Ⅰ > 생산/외주], 수불에 영향 없는 계획·원가(매출계획/생산계획/원가생성·이익현황)는 [재고Ⅱ > 계획관리/이익관리]에 배치. 화면 구성은 공통적으로 (1) 상단 헤더 영역: 일자/전표No/공장(창고)/거래처/담당자, (2) 하단 품목 그리드: 품목코드(돋보기 팝업검색)/품명/규격/수량/단가/적요 라인 반복, (3) 그리드 위 기능 버튼: [주문], [작업지시서 적용], [BOM풀기], [BOR풀기], [소요] 등 이전 전표 불러오기(적용) 버튼 체인으로 주문→작업지시→불출→생산입고→판매가 연결되고 각 단계 잔량(미불출/미생산/미입고)이 자동 관리됨. 생산입고2·3은 [생산]/[소모] 탭 전환 구조. 우측 상단 Option > 입력화면설정(셀프 커스터마이징)으로 필드 추가/제거(예: 외주비 단가/공급가액/부가세, 주문서No)가 가능하고, 모든 조회·출력물은 검색패널(기간/창고/품목/공정 필터) + 그리드 결과 + EXCEL 변환 + 양식설정(자사 전용 서식)을 지원. 품목코드 클릭 시 재고수불부 등으로 하이퍼링크 데이터 추적. 제약: 공장:공정=1:1 매칭, 작업지시서에 지정한 생산공장 외 불출/입고 불가, 생산계획 시작일 당일 고정. 주의: 본 조사 환경에서 ecount.com/매뉴얼 직접 열람이 차단되어(프록시 403) 검색 스니펫 기반 교차확인으로 작성했으며, (확인필요) 표시 항목은 실계정 화면 대조 권장.


### 재고Ⅰ > 기초등록 > 창고등록
*메뉴명: 창고등록 (공장/공정 설정)*

생산관리의 전제가 되는 장소 등록. 구분을 '창고/공장/공장(외주비관리)' 중 선택하며, 공장으로 등록해야 생산 전표(불출/입고) 입력이 가능하다.

**주요 필드**: 창고코드 · 창고명 · 구분(창고/공장/공장(외주비관리)) · 생산공정(코드/명칭/순번)

**기능**:
- 구분 선택: '창고'(입출고 관리용 저장공간), '공장'(입출고 + 우리회사 생산관리), '공장(외주비관리)'(입출고 + 거래처 외주공장 생산관리·외주비 정산)
- 구분을 '공장' 또는 '공장(외주비관리)'로 선택 시 '생산공정' 항목이 활성화됨
- 생산공정 등록: 돋보기 클릭 → 신규 버튼 → 코드/명칭/순번 입력·저장. 순번은 생산 라인·절차 순서를 의미하며 원가계산에 영향을 주므로 공정 순서대로 입력해야 함
- 공장 1개당 생산공정 1개를 1:1로 매칭하는 구조. 실제 공정이 2개(예: 조립→포장)면 공장을 '본사공장1(공정1)', '본사공장2(공정2)'처럼 나눠 등록
- 작업지시서에서 지정한 생산공장이 아닌 다른 공장에서는 해당 지시 건의 생산불출/생산입고 입력 불가(공식 교재 기준)
- 외주공장을 '공장(외주비관리)'로 등록하면 외주공장 내 우리 회사 자재 재고 수불을 실시간 파악 가능

**관련 보고서/출력물**: 창고별재고현황(공장·외주공장 포함 장소별 재고)


### 재고Ⅰ > 기초등록 > 품목등록
*메뉴명: 품목등록 (생산 관점)*

BOM·생산 입력의 전제. 생산품(제품/반제품)과 소모품(원재료/부재료)을 각각 품목으로 등록한다.

**주요 필드**: 품목코드 · 품명 · 규격 · 단위 · 품목구분(제품/반제품/원재료/부재료/상품) · 안전재고 · 최소구매단위 · 시리얼/Lot 사용여부

**기능**:
- 품목구분에서 제품/반제품/원재료/부재료(및 상품) 중 선택 — 이 구분이 BOM 리스트 표출, 원가상세내역서 집계 구분의 기준이 됨
- 품목이 등록되면 BOM(소요량)입력/조회 메뉴 리스트에 생산품이 자동 표시됨
- 안전재고, 최소구매단위 등록 → 발주계획(MRP) 적정 발주수량 자동계산에 사용
- 시리얼/Lot No. 관리 옵션: 생산·입고 주기별 로트 그룹핑, 유통기한/이력 추적에 활용 (이카운트 원가는 기본적으로 품목코드 단위이므로 로트별 원가관리는 품목코드에 로트를 포함시키는 우회 필요)


### 재고Ⅰ > 생산/외주 > BOM(소요량) > BOM(소요량)입력 / BOM(소요량)조회
*메뉴명: BOM(소요량)입력/조회*

제품·반제품 1단위 생산 시 소모되는 반제품·원재료·부재료의 종류와 소요수량을 등록하는 메뉴. 생산입고 시 소모수량 자동계산의 기준이 된다.

**주요 필드**: 생산품목(제품/반제품) · 소모품목 · 소요수량(생산품 1단위당) · 공정(공정관리 사용 시)

**기능**:
- 품목등록된 생산품이 리스트에 자동 표시되고, 생산품 선택 시 팝업창에서 소모품(원·부재료, 하위 반제품)과 소요수량을 입력
- 다단계 BOM 지원: 제품 BOM 안에 반제품을 넣고, 반제품에 다시 하위 BOM을 등록하는 다층 구조(공정 단계별 BOM) 추적 가능
- 공정관리 사용 시 공정별로 소요자재를 나누어 등록
- 정전개: 제품 생산에 필요한 원재료 구성·수량을 트리(Tree) 구조로 조회
- 역전개: 특정 원재료가 어떤 제품 생산에 사용되는지 역방향 조회
- 소요량계산: 생산품 기준으로 BOM 기준 자재소요량을 산출 — 소요자재의 현재고 확인 및 발주 필요량 확인 용도
- 생산입고 전표 작성 시 BOM 기준으로 완제품 수량 증가 + 소모 자재 수량 자동 감소
- 웹자료올리기(엑셀 업로드)로 BOM 대량 등록 가능 (화장품 제조업 활용 사례 확인)
- LOSS율(손실률) 전용 필드 존재 여부 (확인필요) — 실무에서는 소요수량 자체에 로스를 반영(예: 원두 1kg당 생두 1.15kg)하거나 생산입고2 소모탭에서 실소모량으로 수정하는 방식으로 처리

**관련 보고서/출력물**: BOM(소요량)조회, 정전개 조회, 역전개 조회, 소요량계산 결과(자재소요량/현재고 대비 부족수량)


### 재고Ⅰ > 생산/외주 > 작업지시서입력 / 작업지시서조회

제품·반제품에 대한 생산 요청/지시 전표를 작성하는 메뉴. 이후 생산불출·생산입고가 이 전표를 근거로 진행되어 잔량(미불출/미생산)이 관리된다.

**주요 필드**: 일자/No. · 납품처(거래처) · 납기일자 · 품목코드/품명/규격 · 지시수량 · 생산공장 · 공정 · 참고사항(적요) · 주문서No.(추가항목)

**기능**:
- 상단(헤더)에 일자/납품처/납기일자 입력, 하단 그리드에 생산할 제품·반제품과 지시수량 입력
- 품목 라인별로 생산공장 지정 가능(라인·공장별 생산계획 입력) — 지정된 생산공장 외에서는 해당 건 생산불출/생산입고 입력 불가
- [주문] 버튼: 영업 주문서 내역을 불러와 주문 기준 작업지시서 자동 생성(주문생산). 자체 생산계획이면 직접 입력
- 주문서No. 항목을 주문서 메뉴에 추가해 작업지시서와 매핑하면 주문No별 작업지시 이력 추적 가능
- 잔량관리: 작업지시 대비 미불출수량, 작업지시 대비 미생산수량을 자동 집계
- 생산불출입력·생산입고에서 '작업지시서 불러오기(적용)' 시 잔량만 적용하는 잔량적용 기능 존재(공식 유튜브 FAQ 영상 확인), 불러오기 창에서 작업지시서No 검색 지원(시스템 업그레이드 공지 확인)
- 작업지시서 출력(인쇄) 양식 설정 가능 — 기초등록·전표 입력 데이터를 출력물에 표시

**관련 보고서/출력물**: 작업지시서조회, 작업지시서별불출현황(미불출 잔량), 작업지시서별생산현황(미생산 잔량), 생산진행현황(공정별 진행상황)


### 재고Ⅰ > 생산/외주 > 생산불출입력 / 생산불출조회

생산에 사용할 원·부자재를 자재창고에서 공장(자사공장 또는 외주공장)으로 불출(이동)하는 전표. 창고이동과 달리 BOM 기반 산출이 가능하다.

**주요 필드**: 일자/No. · 출고창고(자재창고) · 받는공장(자사공장/외주공장) · 생산품목·생산예정수량(BOM풀기 기준) · 불출품목/수량 · 작업지시서No.(적용 시) · 적요

**기능**:
- [BOM풀기] 버튼: 생산할 제품·수량 입력 후 클릭하면 BOM 기준 소요자재 목록·수량이 자동 산출되어 불출 라인으로 풀림. 산출된 수량은 실제 불출량으로 수정 가능
- BOM풀기 시 하위공정 반제품까지 불러올 수 있고, 각 반/제품별 생산공장 지정 가능
- [작업지시서 적용] 버튼: 작업지시서를 불러와 BOM 기준 자재 산출, 적용할수량 변경 후 BOM풀기 재클릭 시 소요량 재계산, 잔량적용 옵션 지원
- 받는공장: 자사 생산이면 우리회사 공장, 외주 무상사급이면 외주공장(공장(외주비관리))을 지정
- 불출 시점과 생산 시점이 다른 경우(선불출 후생산)의 재공 관리에 사용
- 불출 후 창고별재고현황에서 원재료가 자사창고 수량 / 외주공장(공장) 수량으로 분리되어 조회됨
- 각 공정별로 원재료를 불출하여 다단계 공정 관리 가능

**관련 보고서/출력물**: 생산불출조회, 작업지시서별불출현황, 창고별재고현황(공장 재고 분리 표시), 재고수불부


### 재고Ⅰ > 생산/외주 > 생산입고1

생산실적(완성품 입고) 입력의 가장 단순한 형태. 생산수량만 입력하면 BOM 기준으로 소모자재가 자동 차감된다.

**주요 필드**: 일자/No. · 생산공장 · 입고창고(받는창고) · 생산품목/생산수량 · 외주비 단가/공급가액/부가세(옵션) · Lot No.(옵션) · 적요

**기능**:
- 생산품목·수량 입력 시 BOM 기준 소모수량 자동 계산·차감 (소모 내역 수정용 별도 탭 없음)
- 생산품은 '받는창고'의 재고로 입고 처리, 소모자재는 생산공장 재고에서 차감
- 하나의 전표에 하나의 공장(공정)만 입력 가능
- 실소모가 BOM과 항상 동일한 표준화된 생산(단순 가공업)에 적합
- 우측상단 Option > 입력화면설정으로 외주비(단가/공급가액/부가세) 항목을 추가해 외주 임가공비 입력 가능

**관련 보고서/출력물**: 생산조회(생산입고 내역), 재고수불부(생산 증가/소모 감소 반영), 작업지시서별생산현황


### 재고Ⅰ > 생산/외주 > 생산입고2

생산실적 입력 시 '생산' 탭과 '소모' 탭이 분리되어, BOM 기준 소모량을 불러온 뒤 실소모 품목·수량을 직접 수정할 수 있는 메뉴.

**주요 필드**: 일자/No. · 생산공장(자사/외주) · 입고창고 · [생산탭] 품목/수량 · [소모탭] 품목/수량(수정가능) · 외주비 단가/공급가액/부가세(옵션) · 작업지시서No.(적용) · 적요

**기능**:
- 생산 탭: 생산한 품목·수량 입력 / 소모 탭: BOM 기준 소모품목·수량이 자동 표시되고 품목·수량 직접 수정 가능
- 생산 중 LOSS(로스팅 감모 등)나 BOM과 다른 실사용량 발생 시 실소모량으로 수정 기록 — 정확한 원가·재고 반영
- BOM 미등록 품목도 소모 탭에서 직접 추가 소모 처리 가능
- 하나의 전표에 하나의 공장(공정)만 입력 가능
- Option > 입력화면설정으로 외주비 단가/공급가액/부가세 항목 구성 가능 — 외주공장 생산실적 + 임가공비 동시 입력
- 무상사급 외주 시: 생산입고 입력으로 외주공장 내 우리 원재료 차감 + 제품 수량 증가를 한 번에 처리

**관련 보고서/출력물**: 생산조회, 재고수불부, 작업지시서별생산현황, 창고별재고현황


### 재고Ⅰ > 생산/외주 > 생산입고3

다(多)공정 품목의 공정별 생산실적을 한 전표에서 일괄 입력하는 메뉴. 품목의 공정이 함께 관리된다.

**주요 필드**: 일자/No. · 공정(다중) · 공장(다중) · 생산품목/수량(공정별) · 소모품목/수량(공정별, 조정가능) · 입고창고 · 적요

**기능**:
- 생산입고1·2는 전표당 1개 공장(공정)만 가능하나, 생산입고3는 여러 공장(공정)을 한 전표에 입력 가능
- 각 공정별 생산실적(공정1 반제품 생산→공정2 소모→최종 제품)을 한 전표로 처리해 다공정 전표처리 간소화
- BOM 기준 소모품목·수량을 불러오며 품목·수량 변경 가능, [소모]탭에서 수량조정 가능
- 각 공정별 생산 전표를 일괄 처리해도 무방한 경우(공정간 시차·재공 추적이 불필요한 경우)에 사용 권장 — 공정별 시점 관리가 필요하면 공정별로 생산불출+생산입고1/2 반복 입력
- 공정 순번이 원가 계산 순서에 반영됨

**관련 보고서/출력물**: 생산조회, 공정별 생산진행현황, 재고수불부


### 재고Ⅰ > 생산/외주 > 작업 > 작업내역입력 / 작업일보 / 작업내역현황
*메뉴명: 작업내역입력 / 작업일보 / 작업내역현황 (BOR)*

생산품목별 작업(공정 내 행위)·투입자원·작업시간을 기록하는 메뉴. 재고 수불에는 영향을 주지 않는 실적/능률 관리용.

**주요 필드**: 일자 · 생산공장/공정 · 생산품목/수량 · 작업명 · 투입자원(설비/작업자) · 표준작업시간(BOR) · 실제작업시간 · 작업자

**기능**:
- [BOR풀기] 버튼: 완제품 생산에 필요한 작업과 기준(표준) 작업시간을 불러옴. 상단 생산공장의 공정과 생산품목의 공정이 일치해야 BOR이 풀림
- 투입자원 필드 더블클릭 시 해당 작업에 연결된 자원(설비/인력) 리스트 팝업에서 선택
- 실제 작업시간이 BOR 기준과 다르면 실소요 시간으로 수정 입력
- 작업일보: 공정 내 작업을 수행한 작업자/작업시간 등을 일 단위로 입력·관리
- 작업내역현황: 생산내역별 표준작업시간(BOR기준) vs 실제 작업시간 vs 차이시간 비교 — 생산능률 분석
- 작업내역입력은 재고 수불 미발생 (생산수량·소모는 생산입고 전표가 담당)
- BOR(작업/기준작업시간/투입자원) 사전 등록 메뉴의 정확한 명칭 (확인필요)

**관련 보고서/출력물**: 작업내역현황(표준 대비 실제 작업시간 차이), 작업일보


### 재고Ⅱ > 계획관리 > 생산계획 (매출계획·프로젝트계획조회와 동일 그룹)
*메뉴명: 생산계획 (MPS)*

주문·매출계획을 근거로 일자별 생산계획을 생성하는 메뉴. 재고 수불에는 영향을 주지 않으며 MRP 산출의 입력이 된다.

**주요 필드**: 생산계획기간(시작일=당일 고정) · 품목 · 계획수량 · 일자별 일정 · 반영옵션(미판매/매출계획/미구매/미생산)

**기능**:
- 생산계획 생성 시 반영 변수: 생산계획기간, 미판매(재고Ⅰ>영업관리>미판매현황의 미출고수량), 매출계획(재고Ⅱ>계획관리>매출계획 입력수량), 미구매(발주 후 미입고 수량), 미생산/미소모(작업지시 후 미생산 수량)
- 품목별 생산일정 관리 및 자재 재고 수준 예측(MPS)
- 생산계획기간의 시작일이 당일로 고정 — 당일 입고 원재료가 기초재고에 반영되지 않으므로 생산계획을 다른 입고전표보다 먼저 생성해야 함(컨설팅 실무 팁)
- 주문과 매출계획 기준으로 일자별 생산계획을 만들어 납기 차질 방지
- 생산계획 대비 실적 비교 현황 (확인필요 — 공식 페이지에 진행상황 실시간 보고서 언급은 있으나 메뉴명 미확인)

**관련 보고서/출력물**: 생산계획조회, 매출계획 대비 현황, 계획 대비 실적(확인필요)


### 재고Ⅰ > 구매관리 > 발주계획입력 / 발주계획조회 (+ 생산/외주 > 소요량계산)
*메뉴명: 소요량산출 / 자재소요계획 (MRP) — 발주계획입력*

생산계획·주문·작업지시 기준으로 BOM을 전개해 자재소요량을 계산하고 부족분을 발주로 연결하는 기능.

**주요 필드**: 기준(주문서/작업지시서/생산계획) · 품목/수량 · 현재고 · 안전재고 · 미입고수량 · 미판매수량 · 최소구매단위 · 발주확정수량 · 납기(입고필요시기)

**기능**:
- 발주계획입력의 [소요] 버튼: 반제품/제품 검색 입력 후 계산 처리 — 주문서나 작업지시서 내역을 근거로 BOM 계산하여 산출된 자재를 발주
- 적정 발주수량 자동계산: 현재고, 안전재고, 최소구매단위, 미입고수량, 미판매수량을 반영
- [안전재고미만] 버튼: 안전재고 미만 품목만 불러와 발주계획 일괄 생성
- 발주계획조회의 [수량조정] 버튼: 안전재고/미판매 등 계산항목을 반영해 발주확정수량 결정
- MRP 연계: 계산된 발주수량과 입고 필요 시기를 산출(생산계획 → 자재소요계획)
- 생산불출에서도 작업지시서 근거 BOM 계산으로 공장별 투입량 자동 산출
- 판매입력의 [소요]버튼으로 유상사급용 자재량(BOM) 산출 가능

**관련 보고서/출력물**: 발주계획조회, 소요량계산 결과(부족자재 리스트), 미입고(미구매)현황


### 재고Ⅰ > 생산/외주 (무상사급) + 재고Ⅰ > 구매관리 발주서입력·구매입력 / 영업관리 판매입력 (유상사급·완제품 외주)
*메뉴명: 외주관리 (외주발주 / 외주입고 / 임가공)*

외주공장을 우리 회사 생산과정의 하나로 등록해 외주 재고 수불·진행상황을 실시간 관리. 사급 형태별로 3가지 처리 방식이 있다.

**주요 필드**: 외주공장(공장(외주비관리)) · 거래처(외주업체) · 발주서(품목/수량/납기/상태) · 불출자재/수량 · 생산실적 품목/수량 · 외주비 단가/공급가액/부가세

**기능**:
- 방식1 완제품 외주(자재 미지급): 외주업체를 거래처로 등록 → 발주서입력으로 생산요청 → 입고 시 구매입력으로 완제품 재고 증가. 발주서 상태(접수/발주/완료) 및 미입고 잔량 관리
- 방식2 무상사급: 원재료 구매입력(본사창고 입고) → 생산불출입력으로 외주공장(공장(외주비관리))에 자재 이동 → 외주공장 생산실적을 생산입고1/2로 입력(외주공장 내 우리 원재료 차감 + 제품 증가)
- 방식3 유상사급: 원재료를 외주업체에 판매입력(원재료 재고 감소, 매출 발생) → 완성품을 발주서입력/구매입력으로 매입(제품 재고 증가). 판매입력 [소요]버튼으로 사급자재량 BOM 산출
- 외주비(임가공비) 관리: 생산입고Ⅰ·Ⅱ의 Option > 입력화면설정에서 단가/공급가액/부가세 항목 설정 → 외주 생산실적과 임가공비 동시 입력, 외주비 세금계산서 수취 시 '공장(외주비관리)' 사용
- 외주공장 재고 실시간 조회: 창고별재고현황에서 자사창고 수량과 외주공장 수량 분리 표시
- 외주입고검사: 품질검사 유형 중 외주입고검사로 수입검사 처리 가능
- 외주발주서 전용 별도 메뉴('외주발주서입력') 존재 여부 (확인필요) — 확인된 소스 기준으로는 발주서입력(구매) 및 생산불출+생산입고 조합으로 처리

### 재고Ⅱ > 이익관리 > 원가생성/수정 (월별이익 그룹)
*메뉴명: 원가생성/수정 (생산원가·이익관리)*

구매·생산 전표와 BOM을 근거로 품목별 생산원가·매출원가를 자동 계산하는 메뉴. 노무비/경비를 공정별로 배부한다.

**기능**:
- 신규 버튼 → 기간 설정 → 원가 생성 시작. 사전작업 단계에서 공정별 노무비/경비 등록
- 생산단가 = 소모된 원·부재료 금액 + 해당 공정에 입력한 노무비/경비 합산 (공정 순번 순서대로 원가가 하위→상위로 굴러감)
- 원가계산식: 단가 = 재고금액 ÷ 재고수량 (수량×단가가 아니라 금액/수량에서 단가를 역산)
- 재고단가 평가방법 3종: 총평균법 / 선입선출법(FIFO) / 최종매입가법
- 기말단가 대량 입력: 재고Ⅱ > 이익관리 > 원가생성/수정 > 웹자료올리기(엑셀 업로드)
- 원가/재고/편집제한일자 설정으로 확정 원가 보호, 확정된 재고수량·원가금액 수정 절차 별도 존재
- 공정별/품목별 원가계산 지원(공식 제품 페이지)

**관련 보고서/출력물**: 원가상세내역서(기초/기말재고·재고조정·반품·불량처리·구매/생산/판매·자가사용 항목별), 월별이익현황, 일별이익현황, 품목별 원가/이익률

### 생두(원재료) → 로스팅(공정) → 원두 완제품(제품)
*메뉴명: (적용 시나리오) 커피 로스팅 단순 가공업 매핑 — 참고*

확인된 이카운트 기능을 커피 로스팅(원두 제조)에 대응시킨 구성. 이카운트 전용 로스팅 사례 문서는 미발견이므로 기능 조합은 소스 확인된 범위로 한정.

**주요 필드**: 생두 소요량(수율 반영) · 배치(Lot) No. · 로스팅 공정 경비(가스비 등) · 포장재 소요량

**기능**:
- 품목등록: 생두=원재료, 로스팅원두(벌크)=반제품(선택), 포장 완제품(200g/1kg)=제품, 봉투·박스·라벨=부재료
- 창고등록: 본사창고(자재) + 로스팅공장(구분=공장, 공정=로스팅) — 포장을 별도 공정으로 관리하려면 공장을 하나 더 등록(공장:공정=1:1 규칙)
- BOM 등록: 완제품 1kg당 생두 소요량에 로스팅 감모(업계 실측: 생두 1kg → 미디엄다크 기준 원두 약 870g, 즉 수율 약 87%)를 반영해 생두 약 1.15kg으로 등록 + 포장재 소요량 등록 — LOSS 전용 필드 미확인이므로 소요수량에 로스를 포함하는 방식
- 일상 운영(최소 구성): 구매입력(생두 입고) → 생산입고2 한 장(생산탭: 원두 완제품 / 소모탭: BOM 자동산출 후 배치별 실감모로 수량 수정) — 로스팅처럼 배치별 수율 편차가 있는 업종은 소모탭 수정 가능한 생산입고2가 적합
- 확장 구성: 작업지시서입력(로스팅 배치 지시) → 생산불출입력(생두 불출) → 생산입고2(실적) → 작업지시서별생산현황으로 배치 잔량 관리
- Lot 관리: 로스팅 배치별 Lot No. 부여로 유통기한·회수 추적 (품목코드 단위 원가 한계 유의)
- 원가: 원가생성/수정에서 로스팅 공정에 노무비/가스비 등 경비 배부 → 원두 kg당 생산원가 자동 산출
- 다크/미디엄 등 배전도별 수율 차이는 배전도별 완제품 품목 분리 + 품목별 BOM 소요량 차등으로 대응 (확인필요 — 실사례 미확보, 확인된 기능의 조합)

**관련 보고서/출력물**: 생산조회(일별 로스팅 실적), 재고수불부(생두 소진/원두 생산), 원가상세내역서(원두 kg당 원가)


## 회계관리 (회계I/회계II)

> **화면 특징**: 웹(브라우저) 기반 화면. 최상위에 모듈 탭(재고, 회계Ⅰ, 회계Ⅱ, 급여, 그룹웨어 등)이 있고, 각 모듈 아래에 기능 그룹(회계Ⅰ: 기초등록/FastEntry/매출매입거래/회계거래관리/장부/결산재무제표/전자(세금)계산서/부가세신고, 회계Ⅱ: 자금관리/자금계획/예산/고정자산/비용관리)이 있으며 그 하위에 개별 메뉴가 배치되는 3단 구조. 입력화면은 상단 헤더영역(일자, 거래처, 부가세유형 등)+하단 다행(多行) 그리드로 여러 건을 한 번에 입력하는 형태이며, 공급가액 입력 시 부가세는 유형에 따라 자동계산(단수차이는 직접 수정 가능). 보고서/장부 화면은 상단 검색조건 패널(기간, 거래처, 계정과목, 부서, 프로젝트 등)+탭 전환(예: 재무상태표의 과목별/세목별/(세목)관리용/제출용/표준용 탭, 계정별원장의 계정별/부서별/사원별/현장별/프로젝트별 탭)+조회 그리드로 구성되고, 그리드의 거래처명·금액 등 링크 클릭 시 하위 원장·원천 전표로 드릴다운된다(예: 거래처명 클릭→거래처관리대장Ⅰ). 모든 입력 메뉴는 3가지 데이터 입력방식 지원: 직접입력, 웹자료올리기(메뉴 하단 버튼, 엑셀 양식으로 1회 200건), 엑셀자료올리기(설치형 모듈, 대용량·다중시트 지원). 각 입력화면은 우측상단 [Option]>[입력화면설정]으로 표시 항목을 추가/제거하는 Self-Customizing이 가능하고, Self-Customizing>사용자관리에서 사용자별 메뉴권한/허용권한/확인권한을 설정. 회계전표는 미결→결재중→확인(승인) 상태로 관리되며 전자결재(그룹웨어)와 연동되어 결재 완료 시 장부에 자동 반영. 전자세금계산서 화면은 진행단계(인증서 첨부전/전송대기/전송중/전송완료/이메일발송완료)를 원형 단계 표시+단계별 건수 숫자 클릭 필터로 보여주는 프로세스형 UI.

## 인사/급여관리 (이카운트 ERP 5.0)

> **화면 특징**: 이카운트 ERP 5.0 화면 구성 특징: (1) 상단 대분류 탭 구조 — 인사/급여 기능은 [관리] 탭 아래 인사관리/급여관리/근태관리로, 세무신고는 [세무] 탭, 급여이체는 [회계Ⅰ] 탭에 분산 배치. (2) 각 모듈은 '기본사항등록(코드/항목 설정) → 작업(입력) → 조회/출력(보고서)' 3단 메뉴 패턴을 따름 — 급여관리는 기본사항등록(수당등록/공제등록/사원등록) → 급여작업(급여계산/대장, 명세서-조회) → 조회/출력(급여현황·집계). (3) 리스트(그리드) 화면에서 행 클릭 → 상세/수정 진입, 하단 [신규]/[인쇄]/[확정] 버튼 배치. (4) 급여대장은 사원 행 × 수당/공제 열의 스프레드시트형 그리드이며, 대장별로 표시 열(대상수당/공제)과 대상사원을 설정하는 방식. (5) [Option] 버튼으로 화면·인쇄양식 사용자 설정(Self-Customizing: 메뉴 사용 여부, 입력화면 항목 구성 변경) 지원. (6) 확정/확정취소 상태 개념 — 확정된 급여대장은 수정·삭제·재계산 잠금. (7) 엑셀 업로드(웹자료올리기)·엑셀다운로드가 인사카드/근태/급여 전반에서 공통 지원. (8) 직원 셀프서비스는 별도 포털 UserPay(pay.ecount.com)로 분리 — 명세서 조회, 연말정산 자료 등록, 근태입력. (9) 그룹웨어(전자결재 휴가신청→근태전표, 출/퇴근기록부)와 ERP 근태·급여가 전표 단위로 연동. (10) 4대보험 요율·간이세액표·공휴일은 시스템이 자동 업데이트하므로 별도 요율 등록 화면 없이 자동계산되는 구조.


### 관리 > 인사관리 > 인사카드등록

사원(직원)의 인사정보를 등록·관리하는 마스터 메뉴. 하단 [신규] 버튼으로 사원별 코드를 등록하며, 이 사원코드는 로그인용 사용자ID와 별개로 관리된다.

**주요 필드**: 사원코드(사번) · 성명 · 주민등록번호 · 입사일자 · 부서 · 직위/직급 · 급여은행/계좌번호/예금주 · 세대주 여부 · 부양가족(공제대상 가족수) · 이메일(급여명세서 발송용) · 사진 · 퇴사일자 (확인필요)

**기능**:
- 신규 사원 등록: 인사카드리스트 하단 [신규] 클릭 → 사원코드 부여 (사용자ID와 별개)

- 사원이 많은 경우 엑셀 일괄 업로드 지원 (기 회원가입된 사원정보 업로드, 항목별 작성 기준 준수)

*메뉴명: 출/퇴근기록부 (출퇴근관리)*

직원의 출근/퇴근 시각을 기록·조회하는 메뉴. 로그인 체크, 출입기기 연동, 모바일 GPS 체크를 지원한다.

**주요 필드**: 사원(ID) · 출근시각/퇴근시각 · 근무일자 · 기록방식(로그인/기기/GPS)

**기능**:
- 이카운트 로그인 시 '출근' 체크박스 체크로 출근 기록
- 세콤(에스원)/캡스 등 출입통제기기(카드·지문인식) 연동으로 출퇴근 자동 기록
- 세콤 지문인식 기록 5분 단위 자동 수집
- 모바일 웹 GPS 위치 기반 출퇴근 체크 (별도 앱 아닌 웹 기반)
- 출퇴근 기록과 연장근무 시간 비교·대사(감사) 가능
- 출퇴근 기록을 근태관리 → 급여계산으로 연동

**관련 보고서/출력물**: 출/퇴근기록부, 월별 출퇴근기록 조회


### 관리 > 급여관리 > 급여작업 (급여대장과 동일 구조로 상여 지급분 생성)
*메뉴명: 상여 관리 (상여대장)*

정기 급여 외 상여금 지급을 처리하는 기능. 급여와 같은 귀속연월에 지급 시 소득세 계산방식을 선택할 수 있다.

**주요 필드**: 귀속연월 · 지급일 · 정산기간 · 상여금액

**기능**:
- 상여 지급대장 생성 (지급구분/대상사원 선택) (확인필요: '상여대장' 별도 메뉴명 여부)
- 소득세 계산방식 선택 1: 지정한 정산기간 내 급여+상여 등 모든 지급 소득을 합산하여 소득세 계산
- 소득세 계산방식 선택 2: 이번 지급사항만으로 소득세 계산 (같은 귀속연월에 급여·상여 별도 계산)
- 상여도 근로소득으로 4대보험·소득세(지방소득세) 공제 자동계산
- 명세서 발행·원천세 신고 반영은 급여와 동일 흐름

**관련 보고서/출력물**: 급여(상여)대장, 원천징수부 반영


### 관리 > 급여관리 > 퇴직 관련 메뉴 (퇴직처리/퇴직금추계액)
*메뉴명: 퇴직관리 (퇴직금 계산)*

퇴직자 발생 시 퇴직금과 퇴직소득세를 자동 계산하고, 재직자 중간정산·추계액 확인을 지원하는 기능.

**주요 필드**: 사원 · 입사일자/퇴사일자 · 평균임금 산정기간 급여내역 · 법정외 퇴직금 · 과세이연 계좌(퇴직연금)

**기능**:
- 기존 급여내역과 입사일자 기준 퇴직금 자동계산 (평균임금 기반)
- 법정 외 퇴직금(퇴직위로금 등) 추가 반영 가능
- 퇴직소득세·지방소득세(주민세) 자동계산
- 퇴직연금 과세이연 처리 지원
- 근로기준법에 의거한 재직자 퇴직금 중간(중도)정산 처리
- 퇴직금추계액 확인: 별도 정산처리 없이 재직자의 퇴직금 추계액 조회
- 퇴직처리 완료 시 퇴직소득 원천징수영수증 및 원천징수이행상황신고서에 자동 반영
- 인사발령(퇴직) 처리와 연동 (확인필요: 정확한 메뉴명)

**관련 보고서/출력물**: 퇴직금추계액, 퇴직소득 원천징수영수증, 소득자료집계표


### 세무 > 원천세 (근로소득 외: 세무 > 기타원천세 > 기타원천세입력)
*메뉴명: 원천세 신고 (원천징수이행상황신고서)*

급여·퇴직금·연말정산 내역을 기반으로 원천징수이행상황신고서 등 세무신고 자료를 자동 생성하는 메뉴.

**주요 필드**: 귀속연월 · 지급연월 · 신고구분(매월/반기/수정/연말) · 소득종류(근로/퇴직/사업/기타 등)

**기능**:
- 귀속연월·지급연월이 일치하는 급여/퇴직/연말정산 내역 원천징수이행상황신고서 자동 반영
- 원천징수이행상황신고서 전자파일 다운로드 → 홈택스 직접 신고
- 사업소득, 이자/배당소득, 기타소득 등 근로소득 외 원천세 자료 자동 반영 (기타원천세입력 메뉴에서 소득자별 입력)
- 원천징수이행상황신고서 각종 부표, 소득세확인서 등 별지 서식 제공
- 지급명세서·간이지급명세서(근로소득) 작성 자료 제공, 홈택스 업로드용 엑셀 서식 지원
- 일용근로소득 지급명세서 지원 (일용직 급여와 연동)

**관련 보고서/출력물**: 원천징수이행상황신고서(+부표), 지급명세서/간이지급명세서, 원천징수영수증, 원천징수부, 소득자료집계표, 소득세확인서


### 관리 > 급여관리 > 일용근로대장 (또는 세무 > 기타원천세)
*메뉴명: 일용직 급여관리 (일용근로대장)*

일용직 근로자의 일별 근무기록 기반 급여계산과 일용근로소득 신고를 지원하는 메뉴.

**주요 필드**: 일용직 사원 · 근무일자 · 근무시간 · 근무장소 · 일당(단가) · 계산방식(일별/월별)

**기능**:
- 일용직 근로자 등록 및 일별 근무시간·근무장소 등록
- 등록된 근무기록 기준 사원별 지급액 자동계산
- 일용직 소득세(일 단위 비과세 한도 적용)·4대보험 공제를 계산방식(일별/월별)에 따라 자동계산
- 급여 지급내역 회계 '일반전표' 자동 반영 (노무비 계정 처리)
- 일용근로소득 지급명세서 등 신고자료 생성
- 기타원천세 메뉴를 통한 월별 홈택스 신고 자료 관리

**관련 보고서/출력물**: 일용근로대장, 일용근로소득 지급명세서, 노무비 집계 (확인필요)


### 관리 > 급여관리 > 연말정산 (직원 자료제출: UserPay)

근로소득 연말정산을 지원하는 기능. 직원이 UserPay로 간소화 자료를 제출하면 회사가 정산하여 신고자료에 반영한다.

**주요 필드**: 귀속연도 · 간소화 PDF 자료 · 공제항목(보험료/의료비/교육비/기부금/신용카드 등) · 결정세액/기납부세액/차감징수세액

**기능**:
- 직원이 홈택스 연말정산 간소화 PDF를 다운로드하여 UserPay에 직접 등록 → 연말정산 자료 수집 자동화
- 소득공제신고서 작성·열람 지원
- 연말정산 결과(환급/추가납부)가 원천징수이행상황신고서에 자동 반영 (귀속연월=지급연월 기준)
- 근로소득 원천징수영수증 발급 (UserPay에서 직원 직접 출력)
- 연말정산 세액 자동계산 상세 로직 (확인필요: 공제항목별 입력 화면 구성)

**관련 보고서/출력물**: 근로소득 원천징수영수증, 소득공제신고서, 원천징수이행상황신고서(연말정산분)


### 회계Ⅰ > 계좌/카드 > 급여이체

급여관리에 입력된 급여내역을 불러와 사원 계좌로 급여를 이체하고 이체상태를 실시간 확인하는 메뉴.

**주요 필드**: 지급일 · 사원별 실지급액 · 은행/계좌번호/예금주 · 이체상태

**기능**:
- 지출결의서·급여 내역을 불러와 계좌이체 진행 (ERP 등록 자료 기반이라 회계장부와 이체금액 불일치 방지)
- [계좌이체상태] 항목으로 이체성공/완료 등 실시간 이체현황 확인 (공식 업그레이드 공지로 확인)
- 인사카드에 등록된 사원 급여계좌(은행/계좌번호/예금주) 사용
- 은행 연동: 여러 은행 거래내역 한 화면 조회, 입출금 내역 회계전표 반영

**관련 보고서/출력물**: 급여이체 내역/현황


### 급여계산/대장 > Option > 분개설정 (전표 자동생성)
*메뉴명: 급여 회계반영 (분개설정)*

확정된 급여대장을 회계전표로 자동분개하여 장부에 반영하는 기능.

**주요 필드**: 지급 계정코드(직원급여/임원급여/급여-제조) · 공제 계정코드(예수금) · 실지급 계정코드(미지급금/보통예금) · 거래처(통장계좌) · 귀속연월

**기능**:
- Option > 분개설정에서 계정 매핑 설정 후 귀속연월 급여대장 선택 시 자동분개
- 지급총액: 기본값 '직원급여(판)' 계정, 임원급여(판)·급여(제조) 등으로 변경 가능
- 공제총액: 4대보험 등 공제 합계를 집계할 계정 선택 (통상 예수금 계정)
- 실지급액: 미지급 상태면 미지급금 계정, 지급 완료면 보통예금 계정 선택 + 거래처에 통장계좌 지정
- 일용직 급여는 일반전표(노무비)로 자동 반영

**관련 보고서/출력물**: 급여 회계전표(일반전표)


### 관리 > 급여관리 > 조회/출력
*메뉴명: 급여 조회/출력 (급여보고서)*

급여 지급실적을 다양한 기준으로 집계·조회하는 보고서 메뉴군.

**주요 필드**: 조회기간(귀속연월/지급일) · 부서/사원 · 지급구분

**기능**:
- 급여현황: 부서별/사원별/월별 급여 지급현황 조회
- 연간/부서별 급여 집계
- 지급항목별/공제항목별 집계
- 소득자료집계표 (퇴직금추계 등과 연계)
- 원천징수부: 사원별 원천징수 누적 관리 (소득세 감면 관련 항목 포함)
- 원천징수영수증, 간이지급명세서 등 타업무 필요 보고서 제공
- 타임시트(근무시간표) 목록 보고서
- 전 보고서 인쇄·엑셀다운로드 지원 (ERP 공통)

**관련 보고서/출력물**: 급여현황(부서별/사원별/월별), 연간급여집계, 지급/공제항목별 집계, 소득자료집계표, 원천징수부, 원천징수영수증, 간이지급명세서, 타임시트 목록

## 그룹웨어 및 부가기능 (보강 조사)

> 조사 소스: 이카운트 공식 그룹웨어 소개 페이지·교육 교재, 컨설팅 블로그(중원컨설팅) 검색 요약. 개인용 클론에서는 대부분 축소/제외 대상이며, 아래는 원본 기능의 카탈로그다.

### 그룹웨어 > 전자결재
ERP 전표와 연동되는 결재 기능. 지출결의서·견적서·발주서 등 ERP 문서를 결재 양식으로 올려 결재선을 따라 승인 처리. 결재 진행상태 관리, 결재 완료 시 ERP 반영.
**개인용 판단**: 단일 사용자이므로 **제외**.

### 그룹웨어 > 게시판
- 공유정보게시판: 게시판 생성/권한 설정, 공지·자료 공유, CRM 관리 용도로도 활용
- 업무관리게시판: 칸반 보드 설정, 업무지원 AI 연동(최신 업그레이드)
**개인용 판단**: 간단한 **메모/노트 보드** 1개로 축소.

### 그룹웨어 > 일정관리
회사 전체 일정을 일간/주간/월간 뷰로 관리. 부서/사원별 일정, ERP 데이터(납기 등)와 연계.
**개인용 판단**: **유지** — 기존 앱의 "달력(로스팅 일정)"과 통합. 로스팅 회차·납기·재고실사일을 한 달력에서 관리.

### 그룹웨어 > 쪽지/알림
이메일(E-MAIL), SMS(카카오톡 알림톡), 사내 메신저, 쪽지(APP 알림) 발송. 거래명세서/청구 안내 등 ERP 문서 전송과 연동.
**개인용 판단**: 사내 메신저/쪽지는 제외. **거래처 안내문 생성+클립보드 복사**(기존 앱의 "메시지" 탭)로 대체 구현.

### 그룹웨어 > 업무관리
출/퇴근기록부(ID 기반 체크), 업무일지, ToDo(할일).
**개인용 판단**: ToDo만 간단히 유지(선택), 출퇴근·업무일지 제외.

고객관리(CRM), 파일공유함, 프로젝트별 관리 기능 제공. 프로젝트는 전표의 공통 차원(프로젝트 필드)으로도 존재.

## 기술 레퍼런스 분석 (조사 결과)

### (1) 로컬 단일 사용자 웹앱 스택
**추천**: Vite + React + TypeScript(SPA) 프론트엔드 + 로컬 Node 서버(Hono 또는 Express) + better-sqlite3, DB는 단일 .sqlite 파일. 브라우저(localhost)에서 사용하고 Electron/Tauri 패키징은 생략.

**대안**: Next.js(App Router) + better-sqlite3 — 단일 프레임워크로 끝내고 싶을 때. AI 생성 코드 품질은 동급이나 restart/캐싱 이슈 디버깅 비용이 있음 / Tauri + Vite/React + SQLite — 진짜 '설치형 앱' 느낌을 원하면. Rust 빌드체인이 추가되는 만큼 개인용으로는 과투자 / 순수 HTML + SQLite-wasm(OPFS) — 서버 없이 파일 하나로 배포되는 장점은 있으나 데이터 유실 리스크와 백업 UX 때문에 ERP 원장 보관용으로는 비추천

**근거**: ① 백업: SQLite 단일 파일이라 파일 복사 = 완전 백업(구글드라이브 동기화 폴더에 두면 끝). 반면 순수 브라우저(IndexedDB/SQLite-wasm+OPFS)는 Windows 저장공간 정리·브라우저 데이터 삭제 시 OPFS 데이터가 지워진 사례가 보고되어 있고(SQLite 포럼, PowerSync 리포트), COOP/COEP 헤더 요구·Safari 제약·탭 간 동시성 제한 등 함정이 많아 '사업 데이터 원본'으로 부적합. ② AI 친화성: Claude가 가장 많이 학습한 조합(React+Express/Hono+SQL)이고, better-sqlite3는 동기 API라 async 버그 여지가 적으며 SQL 스키마가 그대로 코드에 보여 AI가 추론하기 쉬움. ③ Next.js+SQLite도 가능하지만 App Router/서버컴포넌트/캐싱 규칙 등 프레임워크 매직이 단일 사용자 로컬 앱에는 과하고, 데스크톱 맥락에서 Next.js는 정적 export 우회가 필요하다는 지적이 있음(DoltHub Electron vs Tauri 비교). ④ 설치: `npm install && npm start` 배치파일 하나면 되고, 기존 Firebase 단일 HTML 대비 오프라인 완전 동작.


### (2) 이카운트식 엑셀형 데이터 그리드
**추천**: Tabulator(MIT, 완전 무료)를 기본 채택. 인라인 편집·클립보드 복사/붙여넣기·범위선택·스프레드시트 모드·가상 스크롤·XLSX/CSV 내보내기가 전부 무료 범위에 포함됨.

**대안**: AG Grid Community — 문서량·AI 학습 데이터가 가장 많아 코드 생성 품질은 최고. 엑셀 붙여넣기 포기 가능하면 유력한 대안 / react-data-grid(MIT) — 엑셀 호환 Ctrl+C/V가 무료 버전에 포함된 경량 대안 / Handsontable — 기능은 최상이나 상업용 유료라 이 프로젝트 취지(무료 개인 도구)와 불일치

**근거**: 라이선스가 결정적 변수. ① AG Grid Community는 MIT지만 이카운트식 사용의 핵심인 범위선택(cellSelection)·엑셀 호환 범위 복사/붙여넣기·컨텍스트 메뉴가 Enterprise($999/dev/년) 전용 — 공식 Clipboard/Cell Selection 문서에 명시. 단순 셀 편집만 필요하면 Community로 충분하지만 '엑셀처럼 붙여넣기'가 막힘. ② Handsontable은 가장 엑셀에 가깝지만 무료 라이선스가 '비상업 용도' 한정 — 커피 로스팅 '사업'에 쓰는 순간 상업 사용이라 연 $1,000+ 유료 대상. 배포 안 해도 사업 운영 목적이면 라이선스 위반 소지. ③ TanStack Table은 headless라 UI를 전부 직접 만들어야 함 — 단, 10~20행짜리 전표 라인아이템 입력 그리드는 TanStack(또는 그냥 controlled <table>)+커스텀 paste 핸들러로 AI가 쉽게 생성 가능하므로 '입력 폼 그리드'는 자작, '조회/장부 그리드'는 Tabulator라는 이원화도 실용적.


### (3) 복식부기/ERP 데이터모델 레퍼런스
**추천**: ERPNext의 스키마를 1순위 레퍼런스로 삼아 축소 이식: 전표헤더(voucher)—분개라인(gl_entry, 차/대변 합계 일치 강제)—품목(item)—재고수불(stock_ledger_entry, append-only)—현재고 집계(bin)—BOM(bom+bom_item) 구조.

**대안**: Odoo account.move/account.move.line + stock.move — 필드 명세 참고용 / Journalize.io 'Elegant DB Schema for Double-Entry Accounting' — transactions/entries 2테이블 + sum=0 제약이라는 최소 스키마 출발점으로 유용

**근거**: ① ERPNext는 GL Entry(모든 회계 원장 기록)와 Stock Ledger Entry(모든 재고 이동의 불변 감사추적) + Bin(성능용 집계) 이중 구조로, 이카운트의 '전표 중심 + 재고수불부' 개념과 가장 유사하고 GitHub에서 소스(general_ledger.py, stock_ledger_entry.py) 열람 가능. 이동평균/FIFO 평가, 재고→회계 자동분개(perpetual inventory) 패턴까지 참고 가능. ② Odoo는 account.move(전표 헤더)/account.move.line(라인마다 debit XOR credit, account_id, partner_id) 모델이 문서화가 잘 되어 있어 분개 테이블 설계의 보조 레퍼런스로 적합. ③ Akaunting은 코어가 단식부기 성격(복식은 별도 앱)이라 레퍼런스 가치 낮음. ④ 커피 로스팅업 특성(생두→원두 배전)은 ERPNext BOM+Stock Entry(제조 입출고) 축소판으로 자연스럽게 매핑됨: 로스팅 1회 = BOM 기반 생두 출고 + 원두 입고 + 수율(loss) 기록.


### (4) 한국 특화 — 부가세/원화 처리
**추천**: 모든 금액을 원 단위 정수(INTEGER)로 저장(KRW는 소수 없음), 공급가액과 세액을 파생값이 아닌 별도 컬럼으로 저장. 세액 = 공급가액×10%에서 원미만 절사(floor)를 기본으로 하되 반올림 옵션을 설정값으로 제공. 합계 입력 시 역산(공급가액=합계/1.1)과 공급가액 입력 두 모드 지원. 표시는 Intl.NumberFormat('ko-KR')로 통일.

**대안**: 세액을 매번 파생 계산 — 1원 차이·수정 이력 문제로 비추천 / 소수점 지원 통화 대비 minor unit(전) 저장 — KRW만 쓸 거면 불필요한 복잡도

**근거**: ① 국고금관리법 제47조에 따라 국세 과세표준 계산 시 1원 미만은 계산하지 않음(절사) — 실무에서는 회계 프로그램이 반올림하고 거래처 계산서는 절사하는 등 방식이 섞여 1원 차이가 빈번히 발생(클리앙/세무상담 사례 다수). 따라서 절사/반올림을 하드코딩하지 말고 설정으로 두고, 세금계산서 대사 시 1원 차이 허용 로직이 필요. ② 라인별 세액 계산 후 합산 vs 합계 기준 세액 계산이 서로 다른 결과를 내므로 '문서 단위 세액 = 라인 세액의 합'으로 규칙을 하나로 고정하고 저장(이카운트도 저장값 우선). ③ 정수 저장이면 부동소수 오차 문제가 원천 차단되고 SQLite INTEGER와 JS number(2^53)로 충분.


### (5) 인쇄 — 거래명세서/견적서
**추천**: 브라우저 인쇄 + @media print CSS(A4 고정 레이아웃, page-break 제어)를 기본으로 하고, PDF는 브라우저의 'PDF로 저장'으로 해결. React 컴포넌트 단위 인쇄는 react-to-print 사용. jsPDF 등 프로그래매틱 PDF 생성은 채택하지 않음.

**대안**: react-to-print + jsPDF 콜백 조합 — 파일 자동 저장이 꼭 필요할 때만 / Puppeteer로 동일 HTML을 PDF화 — 향후 자동 발송 기능 추가 시 확장 경로

**근거**: ① 거래명세서/견적서 같은 고정 양식은 HTML+CSS로 만들면 브라우저 렌더링 엔진이 레이아웃을 책임지므로 품질이 가장 높고, Claude가 HTML/CSS 인쇄 템플릿을 가장 정확하게 생성함. ② jsPDF의 html() 방식은 레이아웃 컨텍스트를 이해하지 못해 확대/요소 크기/페이지 넘침 등 quirk가 많다는 것이 실무 컨센서스(Joyfill 비교 리포트). ③ 단일 사용자 로컬 환경이라 '서버에서 PDF 생성해 이메일 발송' 같은 요구가 없어 headless Chrome(Puppeteer) 파이프라인도 불필요 — 필요해지면 그때 Puppeteer로 같은 HTML 템플릿을 재사용하면 됨. ④ page-break-inside: avoid, @page { size: A4; margin }, 공급자/공급받는자 2단 표 등 한국식 거래명세서 양식은 순수 CSS로 구현 가능.


### 종합 추천 스택 (Opus 4.8 코드 생성 전제)
**추천**: Vite + React + TypeScript + Tabulator(그리드) + Hono/Express + better-sqlite3(+ 필요시 Drizzle ORM) + @media print 인쇄 템플릿. 데이터모델은 ERPNext 축소판(전표/분개, 품목, 재고수불 append-only 원장, BOM). 금액은 원 단위 정수, 부가세 절사 규칙은 설정화.

**대안**: Next.js 풀스택 단일 프레임워크 구성 / SQLite-wasm 서버리스 구성(백업 리스크 감수 시)

**근거**: 모든 구성요소가 MIT/무료이고, 단일 SQLite 파일 백업으로 사업 데이터 안전성이 확보되며, 각 레이어(SQL 스키마, REST API, React 화면)가 명시적이라 AI가 전체 코드를 일관되게 생성·수정하기 가장 쉬운 조합. 기존 Firebase 단일 HTML 앱의 데이터는 일회성 마이그레이션 스크립트로 SQLite에 이관하면 됨.


### 오픈소스 ERP 스키마 레퍼런스 포인트
- ERPNext tabGL Entry: account, debit, credit, voucher_type, voucher_no, posting_date, party_type/party — 모든 회계 트랜잭션이 이 append-only 원장에 기록되며 전표 단위로 차/대변 합계 일치 검증 (github.com/frappe/erpnext/blob/develop/erpnext/accounts/general_ledger.py)
- ERPNext Stock Ledger Entry: item_code, warehouse, posting_date, actual_qty(부호 있는 증감), qty_after_transaction, incoming_rate, valuation_rate, voucher_type/voucher_no — 불변(immutable) 재고수불 원장 + Bin 테이블(item×warehouse 현재고 집계)의 이중 구조, 이동평균/FIFO 평가 지원 (github.com/frappe/erpnext/blob/develop/erpnext/stock/doctype/stock_ledger_entry/stock_ledger_entry.py)
- ERPNext BOM / BOM Item / BOM Explosion Item: bom_item(item_code, qty, qty_consumed_per_unit, source_warehouse, rate), bom_explosion_item(다단계 전개 결과 캐시) — 로스팅(생두→원두) 레시피·수율 관리에 그대로 축소 적용 가능 (erpnext/manufacturing/doctype/bom/, docs.frappe.io/erpnext/user/manual/en/bill-of-materials)
- Odoo account.move(전표 헤더: move_type, partner_id, state) + account.move.line(분개 라인: account_id, debit XOR credit, partner_id) — 송장/전표를 단일 모델로 통합한 설계 (github.com/odoo/odoo/blob/16.0/addons/account/models/account_move_line.py)
- 최소 복식부기 스키마 패턴: transactions(전표) + entries(분개, 전표 내 합계 0 제약) 2테이블 구조 — blog.journalize.io/posts/an-elegant-db-schema-for-double-entry-accounting/
- Akaunting: 코어가 단식부기 성격의 transactions 모델(복식부기는 유료 앱) — 복식부기 레퍼런스로는 부적합, 제외 권고
