## 0. 감사 방법과 핵심 발견

- **App.tsx 전역 타이틀바(L194~204)** 가 모든 화면 위에 `★ + <h2>{메뉴명}</h2> + Option/도움말` 을 이미 렌더한다(전역 크롬, R12/R13 완료·동결). 따라서 개별 화면의 "실물화"란 이 전역 크롬 아래에서 **이미 실물화된 형제 화면과 동일한 아키타입**을 갖추는 것을 뜻한다.
- **판단 기준(형제 아키타입)**: 각 화면을 같은 트리의 이미 실물화된 형제와 나란히 놓고 구분되지 않아야 한다.
  - 목록/조회형 → `VoucherList`(판매조회) / `MasterScreen` realList(거래처리스트) / `ReportScreen` real
  - 현황/결과 리포트형 → `StockScreens`(재고현황·`ReportScreen` real)
  - 입력형 → `RoastInput`(생산입고II) — `voucher-head`/`voucher-lines` + 하단 `저장(F8)` 파랑 스플릿
  - 리포트 시트형 → `StatementPrint`(거래명세서인쇄)
- **`.btn.primary` 는 실물값이 아니다.** `styles.css` 실측:
  - `.btn.primary` = 배경 `--accent` **#1f48d4**, padding **5px 12px** (약간 밝고 좁음)
  - `.btn.r8-primary` = 배경 `--r8-primary` **#1b3da1**, padding **7px 10px** (참고서 §1 실측값)
  - → 주 버튼은 `r8-primary`(+스플릿은 `r8-split`+▲)여야 실물 일치. `.btn.primary` 혼용은 패턴 2 위반.
- **재사용 가능한 실물 클래스는 이미 전부 존재**(신규 CSS 거의 불필요):
  `r8-titlebar`·`r8-star`·`r8-titlebar-right`·`r8-enter-input`·`r8-primary`·`r8-ghost`·`r8-split`·`r8-split-caret`·`r8-pills`/`r8-pill`·`r8-listbar`/`r8-pager`/`r8-period`·`r8-real`(그리드 스코프: 머리글 #F7F8F9·코드링크 `r8-code` #19358C·음수 `r8-neg` #F2DEDE·정렬 ▼)·`r8-report-title`·`r8-report-meta`·`r8-report-bottom`·`r12-report-footer`(`[P:1]`+조회시각)·`r9-preset-bar`·`r9-prod-toolbar`.
  → **패키지 B는 위 기존 클래스만으로 전부 처리 가능(신규 CSS 0).** `styles.css` append는 패키지 A만 필요 시 수행.

## 3. 수정 패키지 분할 (파일 겹침 0)
