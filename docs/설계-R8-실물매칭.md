## 1. API 계약 — `GET /api/mypage` 확장 (양 패키지의 유일한 접점)

파라미터 없음. 응답은 아래 JSON 한 덩어리. **기존 필드(`ym`,`stock`,`receivables_top`,`todos`,`calendar`)는 유지**하고, `sales`는 **줄 단위로 형태 변경**, `messages`·`pnl_ledger`·`tax_invoice` **3필드 신규 추가**.

  "stock": [                            // 유지 (형태 동일)
    { "item_id": 1, "item_code": "P001", "item_name": "에티오피아",

  "todos":           [ /* 유지 — To Do 위젯 */ ],

### 1.1 필드 확정 스펙 (서버가 반드시 이 형태로 반환)

- **`sales` (줄 단위)** — `doc`(doc_type='sale') ⨝ `doc_line` ⨝ `item` ⨝ `partner`, 이번달(`substr(io_date,1,7)=ym`), 정렬 `d.io_date DESC, d.id DESC, dl.line_no ASC`, **`LIMIT 15`(줄)**.
  - `item_name` = `item.name`, `spec` = `item.spec`, `unit` = `item.unit`.
  - `qty` = `doc_line.qty`, `supply` = `doc_line.supply_amt`, `vat` = `doc_line.vat_amt`, `total` = `supply + vat`.
  - `unit_price` = `qty ? Math.round(supply / qty) : 0` (**참고서 §2: 공급가액÷수량 반올림 표기**. 저장된 `doc_line.price`가 아니라 재계산값을 쓴다).
  - `partner_name` = `partner.name` 또는 `null`.
- **`messages`** — 현재 DB에 그룹웨어 쪽지 저장 테이블이 **없다**(`message.mjs`는 거래처 안내문용이라 스키마 불일치). 실물도 이 회사엔 데이터가 없어 "등록된 데이터가 없습니다."로 표시된다 → 서버는 **`[]` 반환**. 필드 shape(`id,content,from_name,created_at`)는 향후 쪽지 기능 대비 확정만 해 둔다. **신규 테이블·마이그레이션 만들지 말 것.**
- **`pnl_ledger`** — `accounting.mjs`의 `/vat-book` 집계 SQL을 `mypage.mjs`에 **로컬 복제**(파일 격리 규칙 준수). `doc_type IN ('sale','purchase')`, 이번달, 정렬 `io_date DESC, id DESC`, **`LIMIT 5`**. `kind`=`sale?'매출':'매입'`, `item_summary`=`첫 품목명 + (라인>1 ? ' 외 N건' : '')`, `supply/vat/total`=`doc.total_supply/total_vat/total_amount`. 데이터 없으면 `[]`.
- **`tax_invoice`** — R8에서는 **`[]` 고정 반환**(실물도 이 회사는 전자계산서 미발행). 향후 `tax.mjs`/`/api/tax-invoices` 최근 5건 재사용 여지만 주석으로 남긴다.

> **mypage.mjs 제약 재확인**: 신규 테이블 없음, 공용 헬퍼(`ledger.mjs`)만 import, 다른 라우트 파일 수정 금지(SQL은 로컬 복제).

### 1.2 클라 타입 (`client/src/types.ts`)

기존 `MyPageSaleRow`를 **줄 단위로 교체**하고 3개 인터페이스를 추가, `MyPageData`를 확장한다. (기존 `MyPageStockRow`,`MyPageReceivableRow`,`MyPageCalendarDay`,`MyPageTodo`는 유지)

```ts
// MyPage 판매현황 위젯 1행 (줄 단위) — GET /api/mypage 의 sales[]
export interface MyPageSaleRow {
  io_date: string;
  doc_no: string;
  item_name: string;
  spec: string;
  unit: string;            // 규격 없을 때 [단위] 폴백 표기용
  qty: number;
  unit_price: number;      // 공급가액÷수량 반올림(서버계산)
  supply: number;
  vat: number;
  total: number;
  partner_name: string | null;
}

// 쪽지함리스트 1행 — GET /api/mypage 의 messages[] (현재 항상 [])
export interface MyPageMessageRow {
  id: number;
  content: string;
  from_name: string;
  created_at: string;
}

// 매입매출장 위젯 1행 — GET /api/mypage 의 pnl_ledger[]
export interface MyPagePnlRow {
  io_date: string;
  doc_no: string;
  kind: '매출' | '매입';
  partner_name: string | null;
  item_summary: string;
  supply: number;
  vat: number;
  total: number;
}

// (세금)계산서진행단계 1행 — GET /api/mypage 의 tax_invoice[] (현재 항상 [])
export interface MyPageTaxInvoiceRow {
  doc_id: number;
  doc_no: string;
  io_date: string;
  partner_name: string | null;
  total: number;
  status: string;
}

export interface MyPageData {
  ym: string;
  stock: MyPageStockRow[];
  sales: MyPageSaleRow[];
  receivables_top: MyPageReceivableRow[];   // 유지(렌더 제외)
  todos: MyPageTodo[];
  calendar: { year: number; month: number; days: Record<string, MyPageCalendarDay> }; // 유지(렌더 제외)
  messages: MyPageMessageRow[];
  pnl_ledger: MyPagePnlRow[];
  tax_invoice: MyPageTaxInvoiceRow[];
}
```

## 3. R8-② MyPage 6위젯 실물화 (`Dashboard.tsx` + `types.ts`)

참고서 §2. **기본 6종·3열**로 교체. 배치(캐논):

```
[재고현황]      [To Do]           [판매현황(넓음)]
[쪽지함리스트]  [To Do 계속]      [매입매출장]
[쪽지함 계속]   [(세금)계산서진행단계 — 열2~3 가로 스팬]
```

- `.widgets` div에 클래스 `mp6` 추가. 6개 위젯 각각에 area 클래스(`w-stock/w-todo/w-sales/w-note/w-vatbook/w-taxinv`) 부여. **`wide` 클래스는 판매현황에서 제거**(area로 배치하므로).
- **미수금 TOP·달력 미니 위젯은 기본 화면에서 렌더 제외**하되 **JSX·계산 코드(`calCells` 등)는 삭제하지 말고 보존**한다. 방법: 파일 상단에 `const SHOW_LEGACY_WIDGETS = false;` 상수를 두고 두 위젯을 `{SHOW_LEGACY_WIDGETS && (…)}`로 감싼다(향후 위젯설정 기능용). 주석으로 "참고서 §2: 기본 제외, 코드 보존" 명시.

각 위젯 렌더 규칙:

1. **재고현황(`w-stock`)** — 컬럼 `품목코드 / 품목명[규격] / 재고수량(우측)`.
   - 품목코드: `blue` 클래스(코드 링크색). 품목명 표기 = `item_name + (spec ? ' ['+spec+']' : ' ['+unit+']')` (참고서 §2: 규격 없으면 `[kg]` 단위 표기).
   - 재고수량: 우측정렬, **음수도 검정 일반**(위 CSS로 `.neg`가 검정). `below_safety ⚠` 표시는 실물에 없으므로 **제거**.
   - 비면 "등록된 데이터가 없습니다."
2. **To Do(`w-todo`)** — 기존 로직 유지. 비면 실물 문구 **"등록된 데이터가 없습니다."** 로 교체(현재 문구 대신).
3. **판매현황(`w-sales`, 넓음)** — 줄 단위. 컬럼 `일자-No. / 품목명[규격] / 수량 / 단가 / 공급가액 / 부가세 / 합계 / 거래처`.
   - 일자-No.: `blue`, 표기 `` `${io_date.replaceAll('-','/')} -${doc_no.split('-')[1]}` `` (doc_no는 `YYYYMMDD-N` 형식, 확인됨).
   - 품목명[규격] = `item_name + (spec ? '['+spec+']' : '['+unit+']')`.
   - 수량 `fmtQty`, 단가/공급가액/부가세/합계 `fmtWon`(우측정렬). 단가는 서버가 준 `unit_price` 그대로.
   - 비면 "이번달 판매 내역이 없습니다."(기존 문구 유지 가능).
4. **쪽지함리스트(`w-note`)** — `messages` 렌더. 컬럼 `보낸사람 / 내용 / 일시`. 항상 빈 배열이므로 실무상 "등록된 데이터가 없습니다." 표시. (shape는 구현해 두되 데이터는 서버가 [] 반환)
5. **매입매출장(`w-vatbook`)** — `pnl_ledger` 렌더. 컬럼 `일자 / 구분 / 거래처 / 품목 / 합계(우측)`. 일자 `blue`. 비면 문구.
6. **(세금)계산서진행단계(`w-taxinv`)** — `tax_invoice` 렌더. 컬럼 `일자 / 거래처 / 금액 / 상태`. 항상 빈 배열 → 문구.

- 헤더 `< 2026/07 > 일정관리` 유지. 위젯 우측 아이콘은 실물 `↗ ✎ ⋮` 톤으로 유지/조정(선택).

## 4. R8-③ 재고현황 결과 실물화 (`ReportScreen.tsx` 확장 + `StockScreens.tsx` + `reportDefs.ts`)

참고서 §3. **검색폼은 기존 R7-b 유지**, **결과 화면만 실물화**. 재사용 가능하도록 **공통 엔진(ReportScreen)에 옵션을 추가**하고, 재고현황(별도 컴포넌트 `StockStatus`)은 같은 CSS 프레임을 직접 사용한다.

### 4.1 `ReportScreen.tsx` — `ReportDef`에 `real` 옵션 추가 (다른 보고서 재사용용)

`ReportDef` 인터페이스에 선택 필드 추가:

```ts
export interface ReportRealOpt {
  centerTitle?: string;        // 중앙 24/700 제목 (예: '재고현황'). 없으면 def.title 사용
  companyLine?: boolean;       // 좌측 "회사명 : {설정 상호}" 줄
  asOfLine?: boolean;          // 우측 기준일 표기(= vals.as_of 또는 오늘)
  negativeField?: string;      // 이 숫자 컬럼이 음수면 셀 배경 #F2DEDE (.r8-neg)
  bottomButtons?: { label: string; primary?: boolean; split?: boolean; stub?: string }[];
}
export interface ReportDef {
  /* …기존 필드… */
  real?: ReportRealOpt;
}
```

`ReportScreen` 렌더 변경(모두 `def.real`가 있을 때만 동작 — 미설정 보고서는 현행 그대로):
- 최상위 `div`에 클래스 `report-screen r8-real` 추가(그리드 실물 스킨 스코프).
- 그리드 위에 실물 헤더 블록: `<div className="r8-report-title">{real.centerTitle ?? def.title}</div>` + `<div className="r8-report-meta"><span>회사명 : {companyName}</span><span>{asOf}</span></div>`.
  - `companyName`은 `GET /api/settings`(기존 `masters.mjs` 제공, `[{key,value}]` 배열) 1회 조회 후 `company_name` 추출. 없으면 빈 문자열.
- `negativeField` 지정 시 해당 컬럼 formatter에서 `if (Number(value) < 0) cell.getElement().classList.add('r8-neg')`.
- `bottomButtons` 지정 시 그리드 아래 `.r8-report-bottom` 바 렌더. `primary`→`btn r8-primary`(+`split`이면 ▲ caret 붙임), 그 외 `btn r8-ghost`. `stub` 문자열이 있으면 `disabled` + `title=stub`. 실제 동작은 `인쇄`=`window.print()` 정도만 연결, 나머지(자동알림 등)는 stub.

> 이 확장으로 재고Ⅰ 출력물의 그리드형 보고서(`stock-flow`,`other-moves` 등)도 `real` 한 줄로 실물 헤더/하단바를 얻는다. R8에선 **재고현황 실물화가 목표**이므로 reportDefs에는 예시로만 적용(§4.3).

### 4.2 `StockScreens.tsx` `StockStatus` — 결과 실물화

- 우측 타이틀바(선택, 실물 §3): 화면 상단에 `.r8-titlebar`(★ 재고현황 + `[입력 후 Enter]` 스텁 input + `Search(F3)` `btn r8-primary`(→ `load()`) + `Option`·`도움말` `btn r8-ghost` disabled). 검색폼과 중복되면 생략 가능 — 최소 요건은 결과 프레임(중앙제목/회사·기준일 줄/음수셀/하단바).

```ts
interface Props<T> {
  /* …기존… */
  realList?: boolean;                 // true면 컨테이너에 'r8-real' 클래스 + 상단 실물 타이틀바

## 7. 서버 작업 상세 (`server/mypage.mjs` 단일 파일)

§1 계약대로 응답을 확장한다. 기존 집계(stock/todos/receivables_top/calendar)는 유지. 변경·추가분:

1. **`sales` 줄 단위 교체** — 기존 doc 단위 6건 집계를 삭제하고, `doc_line` 조인 줄 단위 쿼리로 교체:
   ```sql
   SELECT d.io_date, d.doc_no, i.name AS item_name, i.spec, i.unit,
          dl.qty, dl.supply_amt AS supply, dl.vat_amt AS vat,
          p.name AS partner_name
   FROM doc d
   JOIN doc_line dl ON dl.doc_id = d.id
   JOIN item i ON i.id = dl.item_id
   LEFT JOIN partner p ON p.id = d.partner_id
   WHERE d.doc_type='sale' AND d.io_date >= ? AND d.io_date <= ?
   ORDER BY d.io_date DESC, d.id DESC, dl.line_no ASC
   LIMIT 15
   ```
   매핑: `total = supply + vat`, `unit_price = qty ? Math.round(supply/qty) : 0`. `qty`는 `round1` 적용.
2. **`messages`** — `[]` 반환(신규 테이블 금지). 주석: "그룹웨어 쪽지 저장소 도입 시 채움".
3. **`pnl_ledger`** — `/vat-book` SQL 로컬 복제, 이번달 sale+purchase 최근 5건. `item_summary`는 기존 판매현황 로직처럼 `lineNames`로 생성.
4. **`tax_invoice`** — `[]` 반환. 주석: "tax.mjs /api/tax-invoices 최근 5건 재사용 여지".
