# 00. 현재 업무 분석 — 로스팅 주문관리 앱 (index.html)

> 나만의 ERP를 만들기 전에, 지금 실제로 쓰고 있는 앱(`index.html` 로스팅 주문관리)에서
> 업무 흐름과 데이터를 추출한 문서. 이카운트 클론의 각 모듈이 이 업무를 빠짐없이 흡수해야 한다.

## 1. 사업 개요 (앱에서 확인된 사실)

- **업종**: 커피 로스팅 (원두 도매 중심 — 거래처별 주문 → 로스팅 → 포장 → 배송/전달)
- **설비**: 기센(Giesen) W6 로스터. **1배치 = 5kg 배출** 기준
- **대표 품목**: 하우스블렌드 28,000원/kg, 디카페인 32,000원/kg, 그 외 싯가(주문 시 직접 입력) 품목
- **거래 구조**: 거래처(카페 등)별 kg 단위 주문. 거래처마다 **예외단가**와 **입금주기(당일/월별)** 존재
- **원자재**: 생두(브라질 산토스, 콜롬비아 수프리모 등)를 여러 공급업체에서 kg 단위 구매

## 2. 현재 앱의 탭 구조와 기능

| 탭 | 기능 | ERP 관점 매핑 (이카운트 메뉴) |
|---|---|---|
| 주문입력 | 로스팅 날짜(회차) 선택, 거래처별 주문 체크(누락 방지), 주문 추가(거래처/품목/수량kg/단가/적요), 금액 미리보기 | 영업 > 주문서 입력 |
| 로스팅시트 | 품목별 주문 합산 → 배치 수 자동 계산(÷5 올림), 로스팅 순서 변경(↑↓), 총량 표시 | 생산 > 작업지시서 / 생산계획 |
| 포장리스트 | 거래처별 포장 목록, 항목/거래처 단위 완료 체크 | 물류 > 출하지시 / 피킹리스트 |
| 메시지 | 거래처별 주문확인/택배안내 멘트 생성, 수정 후 복사(자동 저장) | 그룹웨어 > 문자/이메일 발송 |
| 달력 | 월 달력에 로스팅 완료(빨강)/예정(주황) 표시, 일자별 kg 합계, 날짜 클릭 시 상세 | 그룹웨어 > 일정관리 + 생산일보 |
| 미수금 | 거래처별 미수금 자동 청구(단가×수량), 입금 체크, 월별 입금처 일괄 입금 처리 | 영업 > 수금 입력 / 미수금 현황 |
| 생두구매 | 구매 입력(구매일/업체/생두명/수량/단가/메모), 월별 구매 합계, 생두별 최근가·최저가 업체 비교, 전체 구매 내역 | 구매 > 구매 입력 / 구매현황, 재고 > 단가 비교 |
| 설정 | 거래처 관리(입금주기·예외단가), 품목 관리(배치·기본단가), JSON 백업/복원, 회차(날짜별 주문) 비우기 | 기초등록 > 거래처/품목 등록, 데이터 관리 |

## 3. 현재 데이터 모델 (localStorage `roastmgr_v4` + Firebase Firestore 선택 동기화)

- **거래처(customers)**: 이름, 입금주기(당일/월별), 예외단가(품목별)
- **품목(products)**: 이름, 기본단가(빈 값 = 싯가), 배치 기준(1배치 5kg)
- **회차(session)**: 로스팅 날짜, 메모 — 날짜 단위로 주문 묶음 관리(미래 날짜 = 예약)
- **주문(orders)**: 거래처, 품목, 수량(kg, 0.1 단위), 단가(원/kg, 100원 단위), 적요, 포장완료 여부
- **미수금(dues)**: 주문에서 자동 생성(단가×수량), 입금 체크 상태
- **생두구매(purchases)**: 구매일, 업체, 생두명, 수량(kg), 단가(원/kg), 메모
- **메시지(messages)**: 거래처별 멘트 템플릿(주문확인/택배안내), 수정본 저장

## 4. 현재 앱의 한계 → ERP로 해결할 것

1. **재고가 없다**: 생두 구매는 기록하지만 재고 수량을 추적하지 않음. 로스팅 시 생두 차감(수율 반영), 원두 완제품 재고, 재고수불부가 필요
2. **생산 기록이 약하다**: 배치 계산만 하고 실제 투입량/배출량(수율), 배치별 이력(로트)이 없음 → BOM(생두→원두)과 생산입고 필요
3. **회계가 없다**: 매출/매입이 장부로 이어지지 않음. 매출·매입장, 거래처원장, 월별 손익, 부가세 자료(공급가액/세액) 필요
4. **문서 출력이 없다**: 거래명세서, 견적서 출력 불가
5. **판매 vs 주문 구분이 없다**: 주문 즉시 청구로 처리. 주문→판매(출고) 전환 단계 필요
6. **백업이 수동**: JSON 수동 내보내기 → 자동 저장/백업 체계 필요

## 5. 반드시 보존해야 할 강점 (클론에 그대로 이식)

- 거래처 **주문 누락 방지 체크** UI (빨간색 = 미주문 거래처)
- **배치 자동 계산 + 로스팅 순서 조정** 로스팅시트
- 거래처별 **입금주기/예외단가** 개념
- **거래처별 안내 메시지** 자동 생성 + 복사
- 달력 기반 회차(로스팅일) 관리, 미래 날짜 예약
- kg 0.1 단위, 원화 100원 단위 스텝 등 실무에 맞는 입력 편의
